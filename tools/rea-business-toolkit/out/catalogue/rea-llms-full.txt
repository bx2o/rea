# rea analyze-javascript-application

Statically reconstruct a local JavaScript/Electron application

## Arguments

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `path` | `string` | yes | ASAR or extracted application path |

## Options

| Flag | Type | Default | Description |
|------|------|---------|-------------|
| `--maxSemanticNodes` | `number` |  | Maximum retained semantic nodes across the application; defaults to 100000. Worker heap and parent result admission remain enforced. |
| `--maxSemanticNodesPerFile` | `number` |  | Maximum retained semantic nodes per source file; defaults to 20000, additionally bounded by max_semantic_nodes and memory/transfer limits. |
| `--sourcePath` | `array` |  | Exact inventoried file path relative to the application root; repeat to select several. No implicit dependencies. |
| `--maxHeapMb` | `number` |  | Maximum V8 old-space heap in MiB for the isolated JavaScript source analyzer; defaults to 1024. This does not change the CLI/MCP process heap. When REA runs on Bun, which ignores V8 heap flags, Windows instead limits the analyzer's committed memory to this budget plus a 512 MiB runtime reserve; other Bun hosts enforce no limit. |
| `--analysisTimeoutMs` | `number` |  | Maximum startup, analysis and transfer time per JavaScript source, in milliseconds; defaults to 300000. On timeout, return collected partial Evidence and stop the analysis. |
| `--artifactFormat` | `string` | `auto` | Application artifact format |
| `--integrityPolicy` | `string` | `fail` | Behavior when declared application integrity does not match |
