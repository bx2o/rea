# viz — Stremiium Repo Visualization & Learning Environment

Interactive visualization app for the Stremiium `rea` repository: browse every folder/file, see created/changed files, and learn the repo through charts, 3D scenes, animated timelines, and reveal.js decks.

**Plan:** `.kilo/plans/1794948779713-repo-viz-learning-environment.md`
**Task prompts:** `prompts/viz/` (19 briefs) · **Status board:** `prompts/viz/TASK-INDEX.md`

## Views

| Route | View | Source |
|---|---|---|
| `/` | Overview dashboard — stat cards, commits-over-time, type mix, churn, zone distribution | `stats.json` / `/api/stats` |
| `/explorer` | Virtualized file tree + file viewer (markdown render, metadata) | `/api/tree`, `/api/file` |
| `/explorer/view3d` | 3D file-system scene (WebGL, client-only) with stats fallback | `/api/tree`, `stats.json` |
| `/commits` | GSAP-animated commit timeline + per-commit diffs | `/api/commits`, `/api/diff/[sha]` |
| `/globe` | cobe WebGL globe hero | `stats.json` |
| `/learn` | reveal.js learning decks (≥4) | `content/decks/` |
| `/councils` | 16-council interactive graph (SC → CRD → C01–C16 → departments) | `graph.json` |

## Offline-first design

The app serves from committed `public/snapshots/*.json` (generated by the zero-dep `scripts/snapshot.mjs`) when git is unavailable, and falls back to live git via `/api/*` when present. All responses carry `source: "git" | "snapshot"`.

## Run (source-complete)

The UI kit is committed, so no shadcn/registry install is needed to run the app. Only the npm
dependencies have to be fetched once.

```bash
cd viz
pnpm install   # or npm install
pnpm dev       # http://localhost:3000
```

The app's *data* is offline-first: it serves committed `public/snapshots/*.json` when git is
unavailable. See [Offline-first design](#offline-first-design).

## Regenerate snapshots

```bash
pnpm snapshot          # tree/commits/stats/graph/tours JSON from the real repo
node scripts/snapshot.mjs --collapse-rea   # collapse rea/ internals in tree emission
```

## Validate

```bash
pnpm verify    # scripts/verify-viz.mjs — data shapes, coverage, a11y smoke
pnpm exec tsc --noEmit && pnpm build   # build gate (VIZ-023/024)
```

## UI kit (hand-implemented, offline-first)

The shadcn/ui components this app uses are **hand-implemented in `components/ui/`** — they are
committed to the repo, so the app builds and runs with **no network install** (plan §8,
offline-first). They follow shadcn conventions and the same API surface, but they are not
shadcn-registry downloads.

Currently present in `components/ui/` (10 files):

`button` · `card` · `badge` · `separator` · `scroll-area` · `skeleton` · `tabs` · `tooltip` · `table` · `command`

Three components from the curated set are **not** yet in the repo and must be added with the
shadcn CLI:

```bash
cd viz
pnpm dlx shadcn@latest add dialog sheet chart
```

| Component | Extra dependency |
|---|---|
| `dialog` | `@radix-ui/react-dialog` |
| `sheet` | `@radix-ui/react-dialog` |
| `chart` | `recharts` (already a dependency) |

`components.json` is already committed — do **not** run `shadcn init`, it would overwrite the
config (including the `registries` map).

## Registry additions

Third-party shadcn registries are declared in the `registries` map of `components.json` and
installed with `add @<namespace>/<component>`. The shadcn CLI has **no `registry` subcommand**.

```bash
pnpm dlx shadcn@latest add @glass-ui/card
pnpm dlx shadcn@latest add @aceternity/text-reveal-card
```

See [`REGISTRIES.md`](./REGISTRIES.md) for the full 29-registry manifest (VIZ-012): namespace,
purpose, registry URL, per-URL verification status (verified vs unverified) and an example
install command for each. `REGISTRIES.md` is the source of truth — this section is only a
summary.

reveal.js · cobe · lucide-react · next-themes
