# 08 — Stremiium Implications: Nedbank Group

Strategic filter for the Stremiium NeoBank against Nedbank Group.

| # | Finding | Decision | Improvement Stremiium makes |
|---|---|---|---|
| 1 | Managed Evolution (formal, sustained IT transformation) | **ADOPT** | Institutionalise the same programme discipline (roadmap, gates) but cloud-native from day one |
| 2 | Public API Marketplace + API Framework | **ADAPT** | Ship an open API/developer surface for partners — but also expose **on-chain** reward APIs Nedbank lacks |
| 3 | Avo super-app (banking + commerce) | **ADAPT** | Build a super-app that unifies banking + Web3 (crypto, BLT loyalty, collectibles), not just commerce |
| 4 | Greenbacks savings-nudge rewards | **ADOPT** | Fold savings nudges into the `$STM` loop (save → earn → convert/stake) |
| 5 | Investment-conversion redemption (points → investments) | **ADAPT** | Mirror with token → staking/investment conversions |
| 6 | MiGoals low-fee entry account | **BEAT** | Offer clear, transparent near-zero entry with `$STM` fee discounts; undercut opacity |
| 7 | "API-first" as a claim | **AVOID** (as differentiator) | Do not sell API-first as unique vs Nedbank; differentiate on Web3 + rewards transparency |
| 8 | Open API surface widens attack surface | **AVOID** | Pair open APIs with strong mTLS/WAF/rate-limiting (per architecture §8) |
| 9 | No crypto/banking convergence | **BEAT** | FSCA CASP + NeoBank in one app; non-custodial MPC wallet |
| 10 | Savings-centric, non-programmable rewards | **BEAT** | Programmable `$STM` rewards with on-chain, simulatable rules |

## Net position

- **Adopt:** transformation-programme discipline; savings-nudge reward mechanic.
- **Adapt:** open API surface (add on-chain reward APIs); Avo super-app (add Web3 layer); investment conversion (token staking).
- **Avoid:** treating "API-first" as a differentiator; exposing APIs without layered security.
- **Beat:** crypto/banking convergence; reward programmability/transparency; fee clarity.
