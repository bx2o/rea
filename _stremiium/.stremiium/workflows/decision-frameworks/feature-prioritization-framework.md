# Feature Prioritization Framework

**Purpose**: Systematically decide which features to build first  
**Use When**: Quarterly planning, backlog grooming, roadmap debates  
**Owner**: Product Manager + The Strategist  
**Last Updated**: February 18, 2026

---

## Prioritization Dimensions

### 1. Customer Value

- How many customers want it? (Reach)
- How much do they want it? (Impact)
- When do they need it? (Urgency)

### 2. Business Value

- Revenue potential?
- Market positioning?
- Competitive advantage?
- Cost savings?

### 3. Strategic Fit

- Moves us toward vision?
- Enables future features?
- Differentiating capability?

### 4. Execution

- Team expertise available?
- Clear requirements?
- Realistic timeline?
- Known unknowns?

---

## Scoring Model

```
Feature Score =
  (Customer Value × 0.3) +
  (Business Value × 0.3) +
  (Strategic Fit × 0.2) +
  (Feasibility × 0.2)

Each scored 1-10

Example:
Feature A: (8×0.3) + (7×0.3) + (9×0.2) + (8×0.2) = 7.9
Feature B: (9×0.3) + (6×0.3) + (5×0.2) + (9×0.2) = 7.0
Feature A ranks higher
```

---

## Qualitative Factors

- Early adopter feedback
- Sales pipeline impact
- Team enthusiasm
- Known technical debt
- Competitive threats

---

## Portfolio Balance

Don't optimize for single metric:

```
30% Must-haves (debt, fixes, compliance)
40% Strategic (improve positioning)
20% Innovations (explorations)
10% Operational (team tech debt)
```

---

## Periodic Review

- Monthly: Course corrections
- Quarterly: Re-prioritize
- Annually: Strategy alignment
