# SECTION 4: FIFTY+ FAQS, SKILLS & KNOWLEDGE LIBRARY

## 4.1 Document Archiving & Cataloging FAQs (28 FAQs)

**Q1: What documents should be archived?**
A: Categories: (1) **Legal & Compliance:** Contracts, agreements, board minutes, regulatory filings, litigation records. (2) **Financial:** Financial statements, budgets, tax returns, audit reports. (3) **HR & People:** Offer letters, employee files (if legal allows), organizational changes, training records. (4) **Product & Technology:** Product roadmaps, architecture decisions, technical specifications, incident reports. (5) **Decisions & Strategy:** Strategic plans, major decisions, meeting minutes from leadership. (6) **Customer & Revenue:** Customer contracts, major deals, customer communications (if relevant). (7) **Governance:** Board meetings, committee meetings, shareholder communications. Archive everything critical (would be bad if lost), frequently referenced, legally required.

**Q2: How do you organize documents for easy retrieval?**
A: Strategy: (1) **Top-level categories:** Legal, Finance, HR, Product, Decisions, Customer, Governance. (2) **Subcategories:** Under Legal: Contracts, Board Minutes, Policies, etc. (3) **Timeline:** Organize by date (year/month structure common). (4) **Naming:** Consistent file naming: "YYYY-MM-DD_DocumentType_Description.format". (5) **Tagging:** Add tags for cross-category searching. (6) **Owner:** Know who created/owns each document. (7) **Status:** Current, draft, archived, deprecated. (8) **Index:** Searchable index of all documents. Test: Should be easy to find any document from 5 years ago.

**Q3: What's a document metadata and why does it matter?**
A: Metadata = data about the document. Includes: (1) **Title** (document name). (2) **Date** (created, modified, archived). (3) **Author** (who created?). (4) **Category** (type of document). (5) **Tags** (keywords for search). (6) **Version** (if versioned). (7) **Status** (current, draft, archived). (8) **Retention** (keep until when?). (9) **Sensitivity** (public, internal, confidential). (10) **Related documents** (links to related docs). Why: Metadata enables search, organization, compliance tracking. Tools: Standard metadata fields; search systems index metadata.

**Q4: How do you handle document versioning?**
A: Strategy: (1) **Version number:** v1.0, v1.1, v2.0 (major.minor.patch). (2) **Date tracking:** When was each version created? (3) **Change log:** What changed in each version? (4) **Author:** Who made changes? (5) **Rationale:** Why changed? (6) **Keep history:** Maintain all versions (can revert if needed). (7) **Current version:** Mark which version is current. (8) **Archive old versions:** Old versions kept but archived (don't confuse with current). Tools: Git (for code), Google Docs (version history built-in), Confluence (version history), SharePoint (version history). Benefit: Can trace changes over time, see who changed what.

**Q5: How do you securely archive sensitive documents?**
A: Approach: (1) **Encryption:** Encrypt sensitive docs (at rest and in transit). (2) **Access control:** Only authorized people can access (role-based access). (3) **Audit trail:** Track who accesses sensitive docs (for compliance). (4) **Backups:** Multiple backups (redundancy for disaster recovery). (5) **Physical security:** If physical storage, secure location. (6) **Retention:** Keep only as long as required (then destroy securely). (7) **Compliance:** Meet legal requirements for sensitive doc storage. (8) **Threat:** Plan for worst-case (breach, theft, disaster). Examples: Financial documents, customer data, legal documents, trade secrets.

**Q6: What's the difference between archiving and backing up?**
A: **Archiving:** Long-term storage of documents no longer actively used. Goal: Preserve historical documents, free up active storage. Accessed infrequently. **Backup:** Copies of current documents for disaster recovery. Goal: Restore if primary documents lost/corrupted. Accessed might if disaster. Key difference: Archives are historical; backups are current documents. Best practice: Do both. Archive old documents (save costs); backup current documents (recover from disaster).

**Q7: How do you search archived documents efficiently?**
A: Approach: (1) **Full-text search:** Search within document contents (Google-like search). (2) **Metadata search:** Search by title, author, date, tags, category. (3) **Advanced search:** Combine criteria ("contracts signed by John in 2023"). (4) **Faceted search:** Refine by category, date, author. (5) **Autocomplete:** Search suggestions as you type. (6) **Spelling tolerance:** Works if you misspell. (7) **Search analytics:** Track popular searches; improve index. (8) **Relevance ranking:** Most relevant results first. Tools: Elasticsearch (powerful search), Solr (search platform), database full-text search.

**Q8: How do you handle document retention and disposal?**
A: Process: (1) **Define retention:** How long to keep each doc type? (varies: contracts indefinitely, emails 3 years, etc.). (2) **Legal requirements:** Some docs have legal minimums (tax records 7 years, etc.). (3) **Tracking:** Track creation date; know when retention expires. (4) **Review:** Before disposal, confirm no active use. (5) **Destruction:** Securely destroy (shred paper, delete digital with overwrite). (6) **Documentation:** Track what was destroyed, when. (7) **Exceptions:** Legal hold (don't destroy if litigation pending), business need (keep if still useful). Best practice: Conservative retention (unclear? keep longer) unless compliance cost high.

**Q9: How do you migrate documents between systems?**
A: Process: (1) **Inventory:** What documents exist? What format? (2) **Source system:** Extract from old system (export, download). (3) **Transformation:** Convert to new format if needed. (4) **Validation:** Check data integrity (nothing lost, corrupted?). (5) **Import:** Load into new system. (6) **Verification:** Spot check (is data correct?). (7) **Decommission:** Archive old system data; shut down if migrating off. (8) **Documentation:** Document migration process (audit trail). Timeline: 1-3 months for large migrations. Risk: Data loss, corruption, downtime.

**Q10: What's chain of custody in document management?**
A: Chain of custody = documented history of who had document, when, for what purpose. Includes: (1) **Creation:** Who created? When? (2) **Access:** Who accessed? When? For what purpose? (3) **Modifications:** Who changed? When? What changed? (4) **Transfer:** Who gave to whom? When? (5) **Storage:** Where stored? By whom? (6) **Preservation:** Maintained securely? (7) **Destruction:** Who destroyed? When? How? Why important: Legal evidence (chain of custody proves authenticity), compliance, audit trail. Tools: Document management systems log access; audit logs track changes.

**Q11: How should you handle duplicate documents?**
A: Problem: Same document exists in multiple places (creates confusion, inconsistency). Solutions: (1) **Detection:** Tools to detect duplicates (file hashing finds identical files). (2) **Consolidation:** Keep one version, delete others. (3) **Canonical version:** Mark one as "official" (others point to it). (4) **Version history:** If different versions, track differences (not duplicates). (5) **Cleanup:** Regular de-duplication process. (6) **Prevention:** Disable creation if not already exists (tech controls). (7) **Naming:** Strict naming helps prevent (clear names = no duplication). Caution: Don't lose version history while de-duplicating.

**Q12: How do you ensure documents don't get lost?**
A: Safeguards: (1) **Backups:** Regular backups to separate location (disaster recovery). (2) **Redundancy:** Multiple copies in different places. (3) **Off-site storage:** Copy stored off-site (survives local disaster). (4) **Version control:** Track versions (can recover old version if current corrupted). (5) **Access logs:** Know who modified when (can rollback if needed). (6) **Vault/safe:** Physical vault for critical documents. (7) **Procedures:** Defined processes for storage/handling. (8) **Testing:** Test recovery process (make sure restores work). Disaster scenarios: Server crash, accidental deletion, ransomware, physical office fire.

**Q13: How do you catalog historical decision-making?**
A: Approach: (1) **Decision record:** For major decisions, record decision, rationale, alternatives considered, outcome. (2) **Timeline:** When was decision made? (3) **Stakeholders:** Who decided? Who was consulted? (4) **Context:** What problem were we solving? (5) **Assumptions:** What assumptions underlay decision? (6) **Rationale:** Why this decision over alternatives? (7) **Outcome:** Looking back, was it good decision? (8) **Related decisions:** How does this relate to other decisions? Format: Structured template. Tools: Confluence pages, Airtable, custom database. Value: Future decision-makers understand why past decisions made; avoid repeating mistakes.

**Q14: How do you handle document access control?**
A: Approach: (1) **Classification:** Classify docs by sensitivity (public, internal, confidential, secret). (2) **Roles:** Define who can access what (read, edit, admin). (3) **Technical controls:** System enforces access (can't read if not authorized). (4) **Audit:** Log all access (who read, when). (5) **Least privilege:** Give minimum access needed. (6) **Review regularly:** Ensure access still appropriate (remove when leave company). (7) **Sensitive revocation:** Can revoke access if needed (leak, compromise). (8) **Encryption:** Encrypt sensitive docs. Tools: Role-based access control (RBAC), LDAP/Active Directory, permission management in document systems.
