# SECTION 4: RULES, SOPs, & OPERATIONAL FRAMEWORKS

## 4.1 Product SOPs

### SOP 1: Product Discovery Process

**Problem Identification:**

1. User feedback analysis
2. Support ticket review
3. Analytics anomaly identification
4. Competitive gap analysis
5. Internal idea submission

**Problem Validation:**

1. User interviews (5-10)
2. Survey validation (n>100)
3. Quantitative analysis
4. Competitive benchmarking

**Solution Ideation:**

1. Ideation workshop
2. Concept sketches
3. Technical feasibility
4. Business case rough

**Solution Validation:**

1. Prototype testing
2. Concept validation
3. Pricing exploration
4. Build vs. buy analysis

### SOP 2: PRD Development

**PRD Structure:**

1. **Executive Summary:** What and why
2. **Problem Statement:** User pain point
3. **Success Metrics:** How we measure success
4. **User Stories:** Who, what, why
5. **Requirements:** Functional, technical, design
6. **Out of Scope:** What we're not doing
7. **Release Criteria:** Definition of done
8. **Open Questions:** Unknowns to resolve

**Review Process:**

1. Draft PRD
2. Design review
3. Engineering review
4. QA review
5. Stakeholder review
6. Final approval

### SOP 3: Sprint Process

**Pre-Sprint:**

1. Backlog grooming
2. Story estimation
3. Sprint planning prep

**Sprint Planning:**

1. Review goals
2. Pull stories
3. Clarify requirements
4. Confirm capacity
5. Commit to sprint

**During Sprint:**

1. Daily standup
2. Blocker resolution
3. Scope management
4. Quality assurance

**Sprint Review:**

1. Demo completed work
2. Stakeholder feedback
3. Metrics review

**Sprint Retrospective:**

1. What went well
2. What didn't
3. Action items

### SOP 4: Launch Process

**Pre-Launch (2 weeks):**

1. QA sign-off
2. Documentation complete
3. Marketing materials ready
4. Support training done
5. Monitoring configured

**Launch Week:**

1. Phased rollout plan
2. Daily standup
3. Issue triage
4. Metrics monitoring
5. Stakeholder updates

**Post-Launch (2 weeks):**

1. Performance analysis
2. User feedback review
3. Issue resolution
4. Success assessment
5. Learnings documentation

## 4.2 Product Decision Framework

### Prioritization (RICE)

**Reach:** How many users will this impact?
**Impact:** How much will it impact them? (3=high, 2=medium, 1=low)
**Confidence:** How confident are we in the estimates? (%)
**Effort:** How many person-months?

**Score = (Reach × Impact × Confidence) / Effort**
