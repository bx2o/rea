# SECTION 4: FIFTY+ FAQS, SKILLS & KNOWLEDGE LIBRARY

## 4.1 Fifty+ Frequently Asked Questions (FAQs)

### **Category 1: PROCESS MANAGEMENT FUNDAMENTALS (14 FAQs)**

**Q1: What's process mapping and why should you do it?**
A: Process mapping: Visual diagram of how work gets done (steps, sequence, decision points, participants). Why: (1) **Understanding:** Visualize process; identify gaps. (2) **Communication:** Everyone sees same picture. (3) **Analysis:** Easier to spot waste/bottlenecks in diagram than description. (4) **Improvement:** Redesign from visual. (5) **Training:** New employees learn process from map. Tools: Flowchart software (Lucidchart, Visio), even PowerPoint. Typical map: 5-15 steps. Detail: Depends on complexity. Do it: For any repeated process.

**Q2: What are the key elements of a process map?**
A: Elements: (1) **Start/end:** Where process begins/ends. (2) **Steps:** Actions taken (rectangles). (3) **Decisions:** If-then points (diamonds; yes/no paths). (4) **Participants:** Who does each step (swimlanes = horizontal rows per person/department). (5) **Handoffs:** Where work passes from person to person. (6) **Wait time:** Where process waits (note delays). (7) **Timeline:** How long each step? Total duration? Example: Hiring process = Start → Job description written → Post job → Applications received → Screen resumes → Interview candidates → Background check → Make offer → Start work → End. Map shows who does what, in what order, how long.

**Q3: What's the difference between a process and a procedure?**
A: **Process:** What gets done; sequence of activities. Example: "Approve expense report." **Procedure:** Detailed how-to; step-by-step instructions. Example: "Log into Expensify → Enter date, amount, category → Attach receipt → Submit → Wait for manager approval." Relationship: Process = high level. Procedure = detailed. Usually both: Process describes overall flow; procedure documents detailed how-to.

**Q4: What's a bottleneck and how do you identify it?**
A: Bottleneck: Step that slows down entire process. Example: Approvals = slowest step; everything else waits. How to identify: (1) **Timeline:** Measure how long each step takes. Longest = bottleneck. (2) **Observation:** Watch process; where does it back up? (3) **Complaints:** What do people complain about? (4) **Data:** Measure WIP (work in progress); high WIP = bottleneck. (5) **Simulation:** Model process; see where things queue. Address: Parallelize work, eliminate step, add resources, automate.

**Q5: What's waste in a process and what types exist?**
A: Waste: Activities that consume resources but add no customer value. Eight types (from Lean manufacturing): (1) **Transport:** Moving things unnecessarily. (2) **Inventory:** Holding excess materials/documents. (3) **Motion:** Unnecessary hand movements (poor workspace). (4) **Waiting:** Idle time (person waits for approval). (5) **Over-processing:** Extra steps beyond what customer values. (6) **Over-production:** Make more than needed. (7) **Defects:** Rework due to errors. (8) **Underutilized talent:** Not using employee expertise. Example: Approval process with 5 unnecessary reviews = over-processing waste. Identify: Value stream map shows waste clearly. Eliminate: Remove unnecessary steps.

**Q6: What's a standard operating procedure (SOP) and what should it include?**
A: SOP: Written document describing how to do a process. Sections: (1) **Title:** Process name. (2) **Purpose:** Why exists? Who uses? (3) **Scope:** When does it apply? (4) **Steps:** Numbered steps (who does what? in what order?). (5) **Decision points:** If this, then that. (6) **Forms/templates:** Any documents needed? (7) **Timeline:** How long each step? (8) **Exceptions:** What if unusual situation? (9) **Approval:** Who approves/owns? (10) **Version:** What version? When last updated? Length: 2-10 pages. Create: For any repeated process. Update: Whenever process changes.

**Q7: What's cycle time and how do you measure it?**
A: Cycle time: Time from start of process to finish. Example: Hiring process = 4 weeks (job posted → offer made). Components: (1) **Active time:** Time doing work (2 weeks). (2) **Wait time:** Time between activities (2 weeks waiting for approvals). Cycle time = active + wait. Focus: Usually wait time is biggest; reduce wait time to improve cycle time. Measurement: (1) Timestamp start and end. (2) Calculate elapsed time. (3) Calculate average over 10-20 instances. (4) Identify variation (why some faster?). Goal: Usually 30-50% improvement possible through bottleneck removal.

**Q8: What's automation and when should you automate?**
A: Automation: Use tools/technology to do work without human intervention. Examples: (1) Email automation (trigger-based actions). (2) Workflow automation (tools like Zapier, Integromat). (3) Document generation (templates auto-population). (4) Data entry (auto-import vs. manual). Criteria to automate: (1) **Repetitive:** Done same way every time. (2) **High volume:** Happens frequently (time/money worth it). (3) **Low complexity:** Rules-based (not judgment calls). (4) **Technical feasibility:** Possible to automate? (5) **ROI:** Cost to automate < savings. Example: Expense reports = repetitive, high volume, rule-based → Automate. Note: Not everything should be automated; some human judgment valuable.

**Q9: What's Lean methodology and how do you apply it?**
A: Lean: Philosophy to eliminate waste and maximize value. Key principles: (1) **Value:** Define what customers value. (2) **Flow:** Work flows smoothly with no waste. (3) **Pull:** Customer demand pulls work (not push from supply). (4) **Continuous improvement:** Iteratively improve. (5) **Respect:** Engage all employees. Methods: (1) **Value stream mapping:** Identify waste. (2) **Kaizen:** Continuous improvement events. (3) **5S:** Organize workspace (sort, straighten, shine, standardize, sustain). (4) **Kanban:** Visualize work, control WIP. Apply: Often works for manufacturing/operations; adaptable to knowledge work. Effort: 3-12 months implementation. ROI: Usually 20-30% efficiency gain.

**Q10: What's Six Sigma and when should you use it?**
A: Six Sigma: Methodology to reduce defects/variation to very high quality (99.99966% perfect). Philosophy: Data-driven improvement. Methods: DMAIC cycle. (1) **Define:** Process to improve? (2) **Measure:** Baseline performance + costs. (3) **Analyze:** Root causes of defects...? (4) **Improve:** Solutions to reduce defects. (5) **Control:** Maintain improvements. Use: When quality/variation is major issue. Effort/complexity: Extensive data analysis, statistical expertise. Cost: $50K-500K+ for project. Consider: Overkill for many business processes; good for high-consequence processes.

**Q11: What's change management and why does it matter for process improvement?**
A: Change management: How to help people adapt when processes change. Why: (1) People resist change (comfort, uncertainty). (2) Poor adoption → improvement doesn't stick. (3) Can undermine even good improvements. Approach: (1) **Communication:** Explain why change (benefits?). (2) **Involvement:** Let team provide input (increases buy-in). (3) **Training:** Make sure people know how to do new process. (4) **Support:** Help during transition (patience!). (5) **Feedback:** Listen to concerns, improve iteration. (6) **Celebrate:** Recognize improvements worked. Timeline: Change management takes time; don't rush.

**Q12: How do you create a continuous improvement culture?**
A: Culture: Mindset that says "we're always improving." Build: (1) **Empower:** Employees can suggest improvements (shouldn't need permission). (2) **Celebrate:** Recognize improvements (big and small). (3) **Habit:** Make improvement regular (monthly improvement meetings?). (4) **Tools:** Give teams improvement tools (Lean, etc.). (5) **Leadership:** Leaders model improvement (talk about improving). (6) **Small wins:** Start with quick wins (builds momentum). (7) **Measurement:** Measure to show improvements working. Indicator: People regularly suggest improvements; ideas get tried.

**Q13: How do you measure process performance?**
A: Metrics: (1) **Cycle time:** How long process takes. (2) **Cost:** How much process costs? (3) **Quality:** Error/defect rate. (4) **Compliance:** % of process done correctly. (5) **Customer satisfaction:** Happy with outcome? (6) **Throughput:** How many per time unit? (7) **Efficiency:** Output per input (cost, time). Setup: (1) Define metric. (2) Establish baseline. (3) Measure regularly. (4) Report. Tools: Dashboards (Tableau, custom spreadsheets) visualize metrics. Use: Identify what to improve, track progress.

**Q14: How do you involve employees in process improvement?**
A: Approach: (1) **Frontline input:** People doing work know best; ask them. (2) **Teams:** Include relevant people (do work, decision-makers, support). (3) **Workshops:** Facilitated sessions to design improvements. (4) **Suggestion system:** Easy way to suggest improvements. (5) **Idea review:** Regularly review suggestions; implement good ones. (6) **Recognition:** Thank people (especially for good ideas). Why: (1) Better ideas (they know process best). (2) Better adoption (they designed it). (3) Engagement (people feel heard). (4) Continuous improvement (ideas keep flowing).
