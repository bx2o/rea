# SECTION 4: FAQs (20+)

**Q1: What makes good technical documentation?**
A: Clear, accurate, complete, organized, searchable, up-to-date, audience-appropriate, actionable.

**Q2: How do you organize documentation?**
A: By user need (not by org structure). Hierarchy: Concept → Task → Reference. Clear navigation, search, cross-links.

**Q3: What is docs-as-code?**
A: Treat docs like code: Version control, review process, CI/CD, linting, automated tests. Improves quality and collaboration.

**Q4: How do you keep documentation current?**
A: Regular audits, ownership assignments, "docs included" in definition of done, user feedback, automated checks.

**Q5: What is information architecture?**
A: Structuring and organizing information. Taxonomy, navigation, metadata, findability. Foundation of good docs.

**Q6: How do you write for different audiences?**
A: Beginners: Step-by-step, context, why. Experts: Quick reference, shortcuts, troubleshooting. Clear labeling.

**Q7: What is single sourcing?**
A: Write once, publish many. Same source → different formats (web, PDF, help). Reduces duplication, ensures consistency.

**Q8: How do you handle tribal knowledge?**
A: Interview experts, shadow work, encourage contribution, make easy to contribute, recognize contributions.

**Q9: What is a content audit?**
A: Inventory and evaluation. What exists, accuracy, usage, gaps, duplicates, outdated. Regular maintenance.

**Q10: How do you measure documentation success?**
A: Usage analytics, search success, time on page, user surveys, support ticket deflection, accuracy reports.

**Q11: What is minimalist documentation?**
A: Only what's needed. Remove redundancy. Progressive disclosure. Task-focused. Reduces cognitive load.

**Q12: How do you handle versioning?**
A: Version numbers, change logs, archived versions, clear "current" indicator, migration guides for major changes.

**Q13: What makes good screenshots/diagrams?**
A: Clear, annotated, current, consistent style, alt text, not too busy, focused on key information.

**Q14: How do you write effective search?**
A: Synonyms in content, clear titles, metadata, tags, search analytics, autocomplete, filtering.

**Q15: What is the difference between knowledge base and documentation?**
A: KB = customer self-service (FAQs, troubleshooting). Docs = comprehensive reference (API, processes). Overlap exists.

**Q16: How do you get people to write docs?**
A: Make easy (templates), part of process, recognition, training, support from Archivist, show value.

**Q17: What is structured authoring?**
A: Content in modular, reusable chunks (DITA, XML). Enables: Multi-channel publishing, reuse, consistency.

**Q18: How do you handle feedback on documentation?**
A: Easy feedback mechanism, triage, respond quickly, iterate, thank contributors, track patterns.

**Q19: What is content governance?**
A: Policies for creation, review, approval, publication, maintenance, retirement. Ensures quality and consistency.

**Q20: How do you migrate documentation platforms?**
A: Audit current, map to new structure, clean/organize, migrate in waves, redirects, training, sunsetting old.

# SECTION 5: SOPs

## SOP 1: New Documentation

1. Identify need/gap
2. Define audience
3. Research content
4. Create outline
5. Write draft
6. Review (technical + editorial)
7. Add to information architecture
8. Set metadata/tags
9. Publish
10. Announce to stakeholders

## SOP 2: Documentation Review Cycle

1. Generate audit report
2. Review top viewed pages
3. Check for outdated content
4. Verify links
5. Update as needed
6. Track changes
7. Quarterly report to CKO

## SOP 3: Content Migration

1. Audit source content
2. Design target IA
3. Create mapping
4. Clean and organize
5. Migrate in batches
6. Test and validate
7. Set up redirects
8. Train users
9. Decommission old
