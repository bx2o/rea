# SECTION 4: FAQs (20+)

**Q1: What is security architecture?**
A: Structural design of security controls, relationships, principles. Balances security requirements with usability.

**Q2: How do you balance security and business needs?**
A: Risk-based approach, business impact understanding, alternative solutions, phased implementation, clear communication.

**Q3: What is threat modeling?**
A: Structured approach to identifying threats. STRIDE, MITRE ATT&CK, attack trees. Early in design.

**Q4: How do you quantify cyber risk?**
A: FAIR (Factor Analysis of Information Risk). Loss Event Frequency × Loss Magnitude. Annualized.

**Q5: What is zero trust architecture?**
A: "Never trust, always verify." Assume breach, verify explicitly, use least privilege. Identity-centric security.

**Q6: How do you handle shadow IT?**
A: Discovery, risk assessment, enablement vs. blocking, approved alternatives, monitoring, education.

**Q7: What is the difference between vulnerability and risk?**
A: Vulnerability = weakness. Risk = likelihood × impact of exploitation. Not all vulnerabilities are high risk.

**Q8: How do you present technical risk to executives?**
A: Business impact, likelihood in plain terms, scenarios, options with costs, recommendation.

**Q9: What is defense in depth?**
A: Multiple layers of security. No single point of failure. If one fails, others provide protection.

**Q10: How do you assess cloud security architecture?**
A: Shared responsibility model, configuration review, encryption, IAM, monitoring, compliance, data residency.

**Q11: What is SABSA?**
A: Sherwood Applied Business Security Architecture. Business-driven security architecture framework.

**Q12: How do you handle technical debt in security?**
A: Inventory, risk assessment, roadmap, business case for remediation, phased approach, monitoring.

**Q13: What is a security pattern?**
A: Reusable solution to common security problem. Authentication, authorization, encryption patterns.

**Q14: How do you evaluate security vendors?**
A: Requirements, POC, reference checks, architecture fit, support, roadmap, cost, integration, scalability.

**Q15: What is secure by design?**
A: Security built into systems from beginning, not added later. Cheaper and more effective than retrofit.

**Q16: How do you negotiate security requirements with resistant teams?**
A: Understand concerns, offer alternatives, show value, find compromise, escalate if necessary.

**Q17: What is cyber insurance and how to approach?**
A: Risk transfer mechanism. Understand coverage, exclusions, premiums, prerequisites, claims process.

**Q18: How do you stay current with threats?**
A: Threat intel feeds, industry sharing, vendor advisories, conferences, research, red team insights.

**Q19: What is the architecture review board?**
A: Governance body reviewing significant designs. Ensures standards, identifies risks, shares knowledge.

**Q20: How do you measure security architecture effectiveness?**
A: Adoption rate, incident reduction, time to deploy, audit findings, stakeholder satisfaction, risk metrics.
