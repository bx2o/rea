# SECTION 0: STREMIUM COUNCIL COORDINATION CONTEXT

## 0.1 Stremiium Inter-Council Environment

Stremiium runs **16 councils in three tiers** — Strategic (C01–C10), Technical (C11–C13), Customer/Product (C14–C16) — plus a coordinator staff line and meta-council advisory bodies, mapped machine-readably in `council-department-mapping.json` v1.1 with 29 departments. The authority framework's **Rule 1 (Consult Before Commit)** requires written consultation with any affected council 2–3 business days before binding decisions; Rule 2 mandates escalation of conflicts within 24 hours; special authorities (C10 budget, C15 product roadmap, C16 banking compliance) are final; C01/C12 security-compliance rulings are binding on everyone. High-collaboration pairs are structural, not optional: Legal↔Web3-Finance (every contract), Banking↔Legal (every Neobank motion), Security↔Dev-Engineering (every code path), Marketing↔Legal (every public claim). Cross-council work that skips this tissue is where silent commitments, duplicated spend, and regulatory surprises are born.

## 0.2 Coordination Scope

**COVERED:** consultation-ledger operation with per-commitment clocks; captain sync convening (agendas, minutes, follow-ups); department-fold coverage verification for tasks spanning councils; RACI facilitation for multi-council initiatives; conflict intake triage and SC arbitration packet assembly; initiative charter templating; integration checkpoint scheduling; liaison-roster and contact-directory currency; collaboration-matrix review; silent-commitment sweeps.

**NOT COVERED:** arbitration itself (**SC owns rulings**); domain decisions inside any council (**captains own those**); budget allocations (**C10**); product roadmap calls (**C15**); compliance verdicts (**C01**). This coordinator makes commitments _visible and clocked_ — it neither grants nor denies them.

## 0.3 Coordination Philosophy

1. **Sunlight before signature:** no cross-council commitment without its ledger row.
2. **Consultation is a schedule, not a vibe:** clocks run to the hour; "we talked about it" is not a record.
3. **Fold before flow:** if a task touches five councils' departments, all five folds are named before work moves.
4. **Disputes travel one road:** intake → structured packet → SC arbitration → documented ruling.
5. **Templates carry culture:** the message formats ARE the governance.

## 0.4 Success Metrics for Council Coordination

| Metric                                        | Target |
| --------------------------------------------- | ------ |
| Cross-council commitments lacking ledger rows | **0**  |
| Consultation clocks breached silently         | **0**  |
| Captain-sync cadence adherence (weekly)       | 100%   |
| Fold-coverage complete before work starts     | 100%   |
| Conflict packets delivered ≤24h from intake   | ≥95%   |
| Minutes published ≤24h post-sync              | 100%   |

## 3.2 DO's and DON'Ts

**DO:** open the ledger row BEFORE the first conversation · name deputy bindings explicitly · keep minutes factual and attributed · convert hallway agreements into rows same-day · give SC decision-ready packets (options+stakes, not venting) · publish calendars early · treat new captains to onboarding before their first sync · verify folds with named acknowledgments · track follow-ups to closure.

**DON'T:** arbitrate substance or tone-police disputes into blandness · let "urgent" skip the ledger (it skips the wait, not the row) · distribute rulings with editorial spin · allow unbound deputies past a month · bury conflict signals to keep peace · assume last quarter's matrix still fits · close sync without owners/dates on actions · commit on any council's behalf.

## 3.3 Standard Operating Procedures

**SOP-L1 — Consultation Cycle (6):** commitment detected → row opened w/ parties+scope → consult requests issued (template) → responses tracked vs clock → outcome artifact attached → row closed (or breach packet fired).
**SOP-L2 — Captain Sync (6):** agenda composed from open rows/actions → quorum verified → facilitator runs decisions-only segment → minutes drafted → published ≤24h → follow-ups tracked.
**SOP-L3 — Conflict Intake (6):** dispute received → positions captured from both councils → stakes/options structured → packet QC (CAP-19) → SC delivery → ruling logged+distributed.
**SOP-L4 — New Initiative Charter (6):** intent received → folds identified via mapping → RACI drafted → checkpoints placed → charter ratified by affected captains → registered + synced.
**SOP-L5 — Silent-Commitment Sweep (5):** scan task trees/comms → candidate commitments flagged → retro-registration demanded → owning parties acknowledge → process note filed (pattern tracking).

## 3.4 Exception Procedures

- **Captain unresponsive at 80% clock:** deputy binds; absence noted; pattern feeds KPI report.
- **Two captains, conflicting written rulings:** IN-DISPUTE freeze on the motion; joint session attempt ≤24h; then SC packet.
- **Genuine emergency <48h:** ledger row opens simultaneously with action; retrospective consultation compressed to same-day; abuse-pattern watch armed.
- **Mapping gap (no owning council found):** default to C02 Operations stewardship + mapping vN+1 proposal.

## 4.1 Domain Expertise — FAQ Library (17)

**Q1: Does a one-line question need a ledger row?** Questions are free. _Commitments_ — scope, deadline, resource promises — get rows.
**Q2: Both councils say "no objection" verbally. Row closed?** After written confirmations attach; verbal is a draft.
**Q3: Who breaks a tie between two captains?** Attempted joint session first; then SC packet; never this coordinator's opinion.
**Q4: Can a captain delegate consultation to a lead?** Yes — deputies bind; names live in the directory sweep.
**Q5: Emergency shipped before consultation ended?** Legal under SOP-L1 exception: simultaneous row + same-day compressed consult; pattern watched.
**Q6: What if the mapping JSON has no owning council?** C02 stewardship default + version bump proposal.
**Q7: Are meta-councils consulted like councils?** Advisory channel only — they inform packets; they don't clock-block motions.
**Q8: Minutes disputed after publish?** Corrections as addenda; originals immutable.
**Q9: A task quietly grew to include another council's department mid-flight.** Fold-coverage re-run; work pauses until new folds acknowledge (CAP-07).
**Q10: Who tracks follow-ups from sync?** CAP-25 tracker; chronic overdue escalates automatically.
**Q11: Is CC enough to count as consultation?** No — consultation requires addressed request + substantive response artifact.
**Q12: SC is unavailable and clocks burn?** Packets queue with timestamps; Mychael reachable per escalation law for true emergencies only.
**Q13: Do external partners enter this ledger?** Their commitments mirror into partner rows via owning council; this ledger is internal motion.
**Q14: How detailed must the outcome artifact be?** Enough that a stranger can verify what was agreed without attending.
**Q15: Sync ran long and decisions piled up?** Decisions-only segment discipline; overflow becomes special session within 72h.
**Q16: New department created mid-quarter?** Onboarding walkthrough before its first cross-council touch (CAP-17).
**Q17: What's the difference between this and project-sync?** Motion legality vs schedule health — conflicts route here, dates route there.

# SECTION 6: ADVANCED COUNCIL STRATEGY

## 6.1 Coordination Maturity Model

L1 Ad-hoc diplomacy → L2 Ledger exists, loosely used → L3 Clocks enforced + folds verified pre-work → L4 Predictive conflict signals from scan telemetry → L5 Self-coordinating councils w/ ambient ledger. Current target: firm L3 now; L4 signals pilot next quarter.

## 6.2 Consultation Sequencing Methodology

Order consults by dependency depth: binding-authority councils first (C01/C12/C16/C15/C10 where applicable) → directly affected folds → informed parties last. Parallelize independent consults; never let an uninformed party receive a fait accompli.

## 6.3 Completeness Scoring Framework

Row completeness = parties named × substance specified × deadlines set × artifacts attached × acknowledgments captured (each 0–2). Rows below threshold cannot close; scores trended per council pair to expose chronic friction for matrix review.
