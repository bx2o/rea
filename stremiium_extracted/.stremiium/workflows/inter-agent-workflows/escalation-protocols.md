# Escalation Protocols - Inter-Agent Coordination Framework

**Purpose**: Guidelines for escalating issues and decisions  
**Audience**: All agents managing issues  
**Last Updated**: February 18, 2026

---

## Overview

Escalation is the structured process of raising issues that cannot be handled at the current level. This document defines when to escalate, how to escalate, what information to provide, and how escalations are handled.

---

## Escalation Principles

### 1. Early Recognition

**Identify escalation needs early**:

- Don't wait until crisis
- Watch for blocked progress
- Recognize resource constraints
- Anticipate conflicts
- Plan ahead for large decisions

### 2. Clear Criteria

**Know exactly when to escalate**:

- Defined escalation triggers
- Clear decision thresholds
- Authority limits
- Timeframe considerations

### 3. Complete Information

**Provide everything needed to decide**:

- Background and context
- What's been tried
- Options being considered
- Recommendation if applicable
- Timeline/urgency

### 4. Appropriate Channel

**Escalate to right person/level**:

- Don't skip levels unnecessarily
- Escalate to decision authority
- Include impacted parties if appropriate
- Use formal channels

### 5. Accountability

**Everyone knows their role**:

- Who makes decision
- When decision needed
- How decision communicated
- Implementation responsibility

## Multi-Council Escalation Framework (16 Councils)

### Level 1: Within Council (Council Captain)

**Escalation Authority**: Council Captain has authority  
**Decision Maker**: The Council Captain (e.g., Tech-Lead for C11)  
**Response Time**:  
**Examples**:

- Standard day-to-day decisions
- Routine project deliverables
- Normal checkpoints
- Predictable resource needs

**Action**: Handle independently, document

### Level 2: To Subagent or Peer Agent

**Authorization Level**: Specialized expertise needed  
**Decision Maker**: Relevant specialized agent  
**Examples**:

- Specialized skill requires involvement
- Peer agent has relevant expertise
- Parallel coordination needed
- Knowledge required outside current agent

**Process**:

1. Identify relevant agent
2. Brief on situation
3. Request input/decision
4. Integrate feedback
5. Proceed with approach

**Timeline**: 1-2 days for input

### Level 3: To Primary Agent

**Authorization Level**: Agent's domain authority  
**Decision Maker**: Agent responsible for domain  
**Examples**:

- Legal questions → Veritas
- Financial decisions → The Capitalist
- Technical architecture → The Architect
- People decisions → The Guardian
- Strategy decisions → The Strategist

**Process**:

1. Document issue/question clearly
2. Provide context and options
3. Request guidance/decision
4. Wait for direction (or urgency-dependent timeline)
5. Implement guidance or decision
6. Report results back

**Timeline**: 2-4 hours for guidance, varies for decisions

### Level 4: To Sparkling Curious

**Authorization Level**: Executive escalation  
**Decision Maker**: Sparkling Curious  
**Triggers**:

- Major budget decisions (> threshold)
- Org structure changes
- Executive-level conflicts
- Cross-company strategy decisions
- Significant risk acceptance
- Major resource reallocation
- Crisis situations

**Process**: Formal escalation request (see template below)

**Timeline**: 4-24 hours depending on urgency

## Escalation Request Template

### Formal Escalation Request

```
ESCALATION REQUEST

Date: [Date/Time]
Submitted By: [Agent Name]
Category: [Strategic/Resource/People/Operational/Decision Authority]
Urgency: [Routine (2-3 days) / Important (24 hours) / Urgent (4 hours) / Critical (Immediate)]

ISSUE SUMMARY
Brief description: [1-2 sentences]

BACKGROUND & CONTEXT
[Explain situation, how we got here, what's been tried]

CURRENT STATE
- What's happening now: [Description]
- What's blocked: [What can't proceed without resolution]
- Impact if unresolved: [Consequences]
- Timeline: [When is decision needed]

OPTIONS BEING CONSIDERED

Option 1: [Description]
- Pros: [Benefits]
- Cons: [Drawbacks]
- Resource needs: [Required]
- Timeline: [How long to implement]

Option 2: [Description]
- Pros: [Benefits]
- Cons: [Drawbacks]
- Resource needs: [Required]
- Timeline: [How long to implement]

RECOMMENDATION
[If applicable: what agent recommends and why]

REQUIRED DECISION
[Specific question being escalated for decision]

INFORMATION ATTACHED
- [Supporting documents]
- [Relevant data]
- [Analysis]

NEXT STEPS PENDING DECISION
[What will happen once decision is made]
```

## Escalation Response Process

### When Escalation Received

1. **Acknowledge Receipt** (within 1 hour)
   - Confirm understanding
   - Indicate timeline for response
   - Request any additional information

2. **Review & Assess**
   - Understand issue fully
   - Gather additional context if needed
   - Consult with impacted parties
   - Develop options if not provided

3. **Make Decision** (by committed timeline)
   - Decide on resolution
   - Document reasoning
   - Identify implementation approach

4. **Communicate Decision**
   - Inform requesting agent
   - Explain rationale
   - Provide clear next steps
   - Set follow-up timeline

5. **Follow Up**
   - Verify implementation proceeding as planned
   - Track resolution
   - Learn from escalation for future prevention

## Escalation Prevention

### Best Practices to Avoid Escalation

- Clear authority definition upfront
- Good communication between agents
- Regular strategic alignment meetings
- Defined approval thresholds known to all
- Proactive problem identification
- Regular check-ins on progress
- Decision-making authority clearly communicated

### Early Warning Signs

**Watch for these and escalate early**:

- Unclear decision authority
- Resource shortage emerging
- Team conflict starting
- Timeline slipping
- Scope creeping significantly
- Blocked on external dependency
- Policy/compliance question
- Major risk appearing

## Crisis Escalation (Immediate)

### When Immediate Escalation is Needed

- Production outage
- Data breach/security incident
- Customer emergency
- Executive issue
- Regulatory investigation
- Major incident

### Crisis Escalation Process

1. **Alert** Sparkling Curious immediately (phone, not email)
2. **Brief** with situation summary (30 seconds)
3. **Request** immediate authorization/guidance
4. **Implement** as directed
5. **Update** every 15-30 minutes while ongoing
6. **Resolve** and document

## Escalation Culture

### Healthy Escalation Culture

✅ **DO**:

- Escalate early when uncertain
- Provide complete information
- Use formal channels
- Document decisions
- Share learnings
- Build in escalation time

❌ **DON'T**:

- Escalate unnecessarily
- Escalate without trying to resolve
- Go around chain of command
- Escalate without facts
- Blame when escalating
- Ignore escalation guidance
