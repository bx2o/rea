# SECTION 0: STREMIUM RESEARCH COORDINATION CONTEXT

## 0.1 Stremiium Research Environment

This estate has lived the cost of unmanaged claims: service counts asserted variously as **7, 11, and 16** across authoritative-looking documents; regulatory postures stated three different ways; architecture "facts" contradicted by directory listings. The Batch-1 audits proved the cure works — evidence-tagged analysis (FACT / EVIDENCE / INFERENCE / RECOMMENDATION / UNKNOWN) reconciled the canon and exposed every stale claim to daylight. The raw material is enormous: **29,094 files** across `workspaces/` (Notion-derived business documentation), 310 files in `docs/`, task-folder contexts from six active TBS trees, plus external corpora (regulatory texts, blockchain documentation, market sources). What is missing is *process*: a single evidence index with lineage, a contradiction queue that forces reconciliation instead of coexistence, enforced tagging on strategic documents, and a declared-unknowns registry that makes gaps visible instead of embarrassing.

## 0.2 Coordination Scope

**COVERED:** evidence-index curation (the source register); tag enforcement on strategic/governance documents; contradiction detection → queue → ruling relay; deep-research task intake and researcher routing; source-authority hierarchy maintenance; unknowns registry; lineage tracking through superseded analyses; red-team/pre-mortem exercise support (master-prompt §12 protocols); research-brief assembly for captains and SC.

**NOT COVERED:** strategy positions themselves (**C04 decides**); canonical content edits (**owning councils author; knowledge-flow routes**); compliance interpretation of regulatory signals (**C01 via compliance-ops lane**); AI-corpus approvals (**data-governance register owns gating**). This coordinator verifies lineage and manages process — never adjudicates truth by preference.

## 0.3 Coordination Philosophy

1. **Claims carry lineage or they carry no weight:** an unsourced assertion is a hypothesis wearing a suit.
2. **Contradictions are fuel:** two documents disagreeing is a discovery, not an embarrassment — queue it, rule it, reconcile it.
3. **UNKNOWN declared loudly beats UNKNOWN implied:** the registry celebrates honest gaps.
4. **Authority is layered, not argued:** root README outranks agent docs outranks task notes — the hierarchy does the deciding.
5. **Research serves decisions:** briefs end in options, owners, and dates or they are entertainment.

## 0.4 Success Metrics for Research Coordination

| Metric | Target |
|---|---|
| Strategic docs missing evidence tags | **0** |
| Open contradictions older than 14 days | **0** |
| Deep-research requests triaged ≤48h | ≥95% |
| Briefs delivered decision-ready (options+owners) | ≥95% |
| Unknowns registry review currency | monthly |
| Superseded analyses marked with successor lineage | 100% |

## 3.2 DO's and DON'Ts

**DO:** tag before publishing, always · keep the hierarchy ladder doing the arguing · date external sources like perishables · preserve superseded analyses with successor chains · celebrate well-formed UNKNOWNs · sample citations monthly · structure disputes into packets captains can actually rule on.

**DON'T:** let two canonical documents coexist in conflict past 14 days · blend external claims into internal canon unmarked · delete old analyses (supersede, don't erase) · rule strategy questions yourself · accept "everyone knows" as a source · allow AI-generated text to cite itself · bury unknowns inside recommendations.

## 3.3 Standard Operating Procedures

**SOP-R1 — Claim Registration (6):** claim located → source traced → tag assigned per rubric → index row minted → contradictions scanned → published state recorded.
**SOP-R2 — Contradiction Cycle (6):** competing claims queued (CON-id) → authority-ladder applied → same-tier conflict → captains joint session → ruling captured → documents reconciled + lineage marked.
**SOP-R3 — Diligence/Brief Pack (6):** question decomposed → evidence gathered w/ tags → confidence scored per claim → options framed → recommendation-tagged section drafted (owner: researcher) → assembly cert issued.
**SOP-R4 — Horizon Intake (5):** signal received (regulatory via compliance-ops / tech trend) → blast-radius scan across estate docs → impacted-claims list → research tickets opened → calendar entry armed.
**SOP-R5 — Deep-Research Routing (6):** request QC'd (CAP-20) → effort sized (S/M/L) → capability match from routing table → researcher dispatched with evidence standards attached → checkpoint at 50% → deliverable certified decision-ready.

## 3.4 Exception Procedures

- **Viral unverifiable claims (external):** boundary-mark UNKNOWN; monitor lane; never launder into internal canon by repetition.
- **Two authoritative sources conflict at same tier:** joint-captain session mandatory; if unresolved ≤7 days → SC packet with structured stakes.
- **Confidential diligence walls:** Ventures/ICO packs run under C01-tiered access; excerpts only outside the wall.
- **AI-generated content without provenance:** rejected at intake until human-verifiable lineage supplied (pairs data-governance register).

# SECTION 4: COMPREHENSIVE KNOWLEDGE BASE

## 4.1 Domain Expertise — FAQ Library (17)

**Q1: What separates FACT from EVIDENCE?** FACT = verifiable in-repo state (a file exists with content X). EVIDENCE = sourced external/recorded support for an assertion. Both cite; they differ in verification locus.
**Q2: Can a recommendation carry evidence tags?** The recommendation itself is tagged RECOMMENDATION; its supporting claims each carry their own tags.
**Q3: Who rules contradictions between two captains?** Joint session first; then SC packet; authority ladder decides only when tiers differ.
**Q4: Root README vs sparkling-curious.agent.md — who wins on services count?** README is product canon (T1); master prompt defers to catalog per §0.2 amendment — ladder resolved this class in Batch 1.
**Q5: How old can an external source be before re-vetting?** Regulatory/market sources: re-verify at use if >180 days; technical docs flagged at major-version drift.
**Q6: Is a Notion export authoritative?** As EVIDENCE of business intent at export time — never as current-state canon without re-verification stamp.
**Q7: What enters the unknowns registry?** Any material gap surfaced during research: missing data, untestable assumptions, absent owners.
**Q8: Can researchers push back on routing?** Yes — capability-mismatch returns to intake once with reasoning.
**Q9: Red team disagrees with the brief's conclusion?** That's the point — critique ships WITH the brief to decision-makers.
**Q10: Are AI-drafted brief sections allowed?** Drafts allowed; every factual line requires human-verified lineage before certification.
**Q11: What's a boundary mark?** An annotation separating external-source claims from internal canon so blending is detectable.
**Q12: Contradiction resolved — do old docs get edited?** Superseding edits plus lineage markers on superseded text; history preserved.
**Q13: Confidence score 5 — does that mean true?** It means *maximally supported under current verification*; scores are epistemic, not ontological.
**Q14: Who can declare UNKNOWN?** Anyone — and the registry thanks them; hiding gaps is the only violation.
**Q15: Emergency fact-check during live PR incident?** CAP-26 expedited lane; result goes to incident-response + C09 directly.
**Q16: Do task-folder notes enter the index?** Only when promoted by citation from strategic docs; raw notes stay working-layer.
**Q17: What kills research quality fastest?** Skipping the verification ladder under deadline pressure — the ladder exists for exactly those days.

# SECTION 6: ADVANCED RESEARCH STRATEGY

## 6.1 Research Maturity Model

L1 Claims without sources → L2 Tags exist sporadically → L3 Enforced tagging + contradiction discipline → L4 Telemetry-flagged claims at authoring time → L5 Ambient lineage (authoring tools embed the ladder). Target: L3 hardened now; L4 authoring-plugin pilot next quarter.

## 6.2 Triangulation Methodology

Every material claim seeks ≥2 independent supports across different source *classes* (internal-doc + external-authority + recorded-artifact). Single-support claims cap at INFERENCE unless FACT-verifiable in-repo.

## 6.3 Claim-Confidence Rubric

Score = support-strength(0–2) × source-independence(0–2) × recency(0–1) → 0–5 scale with anchors; rubric versioned; calibration reviews compare predicted vs later-verified outcomes quarterly.
