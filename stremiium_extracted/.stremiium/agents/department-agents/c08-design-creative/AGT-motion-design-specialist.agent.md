# SECTION 4: KEY FAQS & KNOWLEDGE LIBRARY

## 4.1 Motion Design FAQs

**Q1: When should you use animation?**
A: Purposes: (1) **Feedback:** Confirm user action. (2) **State change:** Show what happened. (3) **Orientation:** Where am I? Where did I come from? (4) **Delight:** Surprise and pleasure. (5) **Education:** Show how something works. (6) **Loading:** Entertainment during wait. Avoid: Decoration without purpose, excessive motion that distracts.

**Q2: What makes good animation timing?**
A: Principles: (1) **Speed:** Fast enough to feel responsive, slow enough to perceive. (2) **Easing:** Acceleration/deceleration feels natural. (3) **Duration:** Complex = longer, simple = shorter. (4) **Rhythm:** Consistent timing language. (5) **Responsiveness:** Immediate reaction to input. Guidelines: Micro-interactions 100-300ms, transitions 300-500ms, page animations 500-800ms.

**Q3: How do you balance delight with performance?**
A: Strategies: (1) **Optimize:** Small file sizes, efficient code. (2) **Prioritize:** Animate what matters most. (3) **Conditional:** Reduce for low-power devices. (4) **Test:** Measure frame rate. (5) **Progressive:** Enhance, don't require. (6) **Lazy load:** Animate when visible. Performance budget: Allocate animation performance like any resource.

**Q4: How do you create accessible animations?**
A: Requirements: (1) **Respect prefers-reduced-motion:** Disable or reduce for users who request. (2) **No vestibular triggers:** Avoid large, fast motion that causes nausea. (3) **No flashing:** Avoid strobe effects. (4) **Optional:** Animation shouldn't be required to use product. (5) **Test:** With assistive technologies. Principle: Motion should enhance, never impede.

**Q5: What's the difference between Lottie and CSS animations?**
A: **Lottie:** Complex vector animations from After Effects. Pros: Rich, detailed, design tool workflow. Cons: Larger files, JSON parsing overhead. **CSS:** Simple transforms, opacity, color. Pros: Performant, native, small. Cons: Limited complexity. Use: CSS for simple UI transitions, Lottie for complex illustrations and icons.

**Q6: How do you document animations for developers?**
A: Documentation: (1) **Video reference:** Screen recording of intended motion. (2) **Specs:** Duration, delay, easing values. (3) **Prototype:** Interactive version. (4) **Assets:** Exported files (Lottie JSON, video, GIF). (5) **Code examples:** Reference implementations. (6) **Variations:** Different states/sizes. Tools: After Effects, Figma Smart Animate, Principle, Framer.

4. **Consistent:** Same language throughout

## 6.2 Timing Scale

| Type           | Duration  |
| -------------- | --------- |
| **Micro**      | 100-200ms |
| **UI**         | 200-400ms |
| **Transition** | 300-500ms |
| **Page**       | 400-800ms |
| **Ambient**    | 2000ms+   |

## 6.3 Easing Functions

- **Ease-in:** Acceleration (entering)
- **Ease-out:** Deceleration (exiting)
- **Ease-in-out:** Both (screen transitions)
- **Spring:** Bouncy, organic
- **Linear:** Constant speed (rare)
