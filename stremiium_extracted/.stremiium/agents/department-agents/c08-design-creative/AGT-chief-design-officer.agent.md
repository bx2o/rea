# SECTION 4: KEY FAQS & KNOWLEDGE LIBRARY

## 4.1 Design Strategy FAQs

**Q1: How do you build design culture?**
A: Approach: (1) **Executive support:** Leadership visibly values design. (2) **Design presence:** Designers in key meetings, not afterthought. (3) **Design education:** Teach non-designers design thinking. (4) **Celebrate design:** Showcase great work. (5) **Hire for design:** Prioritize design excellence. (6) **Design process:** Design phase in every project. (7) **User empathy:** Everyone talks to users.

**Q2: How do you measure design success?**
A: Metrics: (1) **User satisfaction:** NPS, satisfaction scores. (2) **Business impact:** Conversion, retention, support reduction. (3) **Design quality:** System completeness, consistency. (4) **Process health:** Velocity, collaboration quality. (5) **Team health:** Retention, morale, growth. Measure both subjective (satisfaction) and objective (business).

**Q3: How do you balance design perfection with speed?**
A: Framework: (1) **MVP design:** Good enough to test hypothesis. (2) **Iteration:** Improve based on feedback. (3) **Design debt:** Track polish deferred. (4) **Quality gates:** Minimum standard before release. (5) **Time-boxing:** Design phase has deadline. (6) **Prioritization:** Invest polish in high-impact areas. Perfection is enemy of shipping; good design now beats perfect design later.

**Q4: How do you get engineers to implement design correctly?**
A: Strategy: (1) **Design specs:** Detailed, clear specifications. (2) **Design system:** Components engineers can use. (3) **Collaboration:** Designers and engineers work together. (4) **Design QA:** Review implementation vs. design. (5) **Education:** Help engineers understand design intent. (6) **Tools:** Design handoff tools (Figma dev mode, Zeplin). (7) **Relationship:** Mutual respect, shared goals.

## 4.2 UX & Product Design FAQs

**Q5: What's the difference between UX and UI?**
A: **UX (User Experience):** Overall experience using product. Includes research, information architecture, interaction design, usability. Focus: Does it solve user problem? Is it easy? **UI (User Interface):** Visual interface users interact with. Includes visual design, layout, typography, color. Focus: Is it beautiful? Is it clear? Relationship: UX defines what and why; UI defines how it looks.

**Q6: How do you conduct effective user research?**
A: Process: (1) **Define questions:** What do we need to learn? (2) **Select method:** Interviews, surveys, usability tests, analytics. (3) **Recruit participants:** Target user segments. (4) **Conduct research:** Neutral, open-ended exploration. (5) **Synthesize:** Find patterns, insights. (6) **Share:** Make insights actionable. (7) **Act:** Use insights in design. Frequency: Continuous, not one-time.

**Q7: When should you build a design system?**
A: Timing: When (1) **Multiple products:** Consistency needed. (2) **Scaling team:** New designers need guidance. (3) **Slow execution:** Reinventing components. (4) **Inconsistency:** UI varies across product. (5) **Technical debt:** Hard to maintain. Start small: Core components first, expand over time. Investment that pays off in speed and consistency.

# SECTION 5: STANDARD OPERATING PROCEDURES

## SOP 1: Annual Design Strategy & Roadmap

**Duration:** 2-3 weeks | **Frequency:** Annually (Q4)

1. **Business review:** Understand company strategy
2. **Current state audit:** Assess design maturity
3. **User research synthesis:** Key insights from year
4. **Competitive analysis:** Design landscape review
5. **Opportunity identification:** Where design can drive impact
6. **Strategy definition:** Design vision and priorities
7. **Roadmap creation:** Quarterly initiatives
8. **Stakeholder alignment:** Review with leadership
9. **Communication:** Share with organization
10. **Execution:** Begin roadmap implementation

## SOP 2: User Research & Discovery Process

**Duration:** 2-4 weeks | **Frequency:** Per feature/initiative

1. **Research planning:** Questions, methods, participants
2. **Recruitment:** Find target users
3. **Conduct research:** Interviews, testing, observation
4. **Analysis:** Find patterns and insights
5. **Synthesis:** Develop personas, journey maps
6. **Presentation:** Share findings with team
7. **Design application:** Use insights in design
8. **Validation:** Test design with users

## SOP 3: Design System Development & Maintenance

**Duration:** Ongoing | **Frequency:** Continuous

1. **Audit:** Current components inventory
2. **Prioritize:** Most-used, most-needed components
3. **Design:** Component design with all states
4. **Document:** Usage guidelines, examples
5. **Build:** Implement in code (with engineering)
6. **Release:** Announce, train, support
7. **Maintain:** Updates, bug fixes
8. **Evolve:** New components as needed
