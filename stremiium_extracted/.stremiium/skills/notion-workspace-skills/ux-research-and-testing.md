# UX Research & User Testing - Skill Guide

**Skill Category**: Design/UX  
**Level**: Intermediate to Advanced  
**Time to Proficiency**: 6-8 weeks  
**Last Updated**: February 18, 2026

---

## Overview

User Experience is more than aesthetics—it's understanding users deeply and designing solutions that work for them. This skill covers research methods, testing, and analysis.

---

## Core Concepts

### 1. User Research Methods

**Quantitative Research** (Numbers, metrics)

- Surveys: Ask many people questions
- Analytics: Track how users behave
- A/B Testing: Compare two versions
- Usability metrics: Completion rate, time, errors

**Qualitative Research** (Stories, insights)

- Interviews: Deep conversations
- Observations: Watch users in natural environment
- Focus groups: Group discussion
- User testing sessions: Watch users try product

### 2. Research Process

```
1. Define Question
   "Do users understand payment process?"

2. Plan Research
   "Who (5-8 current users), How (user testing)"

3. Recruit Participants
   "Screen for relevant characteristics"

4. Conduct Research
   "Run sessions, take notes"

5. Analyze Data
   "Look for patterns, themes"

6. Communicate Results
   "Present findings to team"

7. Iterate Product
   "Make changes based on learning"
```

### 3. User Personas

**Create Based on Research**

```
Name: Sarah Johnson
Role: Busy professional
Age: 35
Pain Points:
- Limited time
- Tech-averse
- Needs simple solutions

Goals:
- Quick transactions
- Clear information
- Minimal clicks

Behaviors:
- Uses mobile mostly
- Prefers phone support
- Shares recommendations
```

## Research Methods in Detail

### Method 1: User Interviews (Qualitative)

**Best for**: Understanding motivations, pain points

**Structure**:

1. Welcome & rapport (5 min)
2. Background questions (5 min)
3. Experience questions (15 min)
4. Scenario questions (10 min)
5. Thank you (5 min)

**Questions**:

- Open-ended: "Tell me about your experience..."
- Probing: "Why did you do that?"
- Hypothetical: "If you could change one thing..."

### Method 2: Usability Testing (Quantitative + Qualitative)

**Best for**: Identifying specific problems

**Setup**:

1. Recruit 5-8 users
2. Create scenario: "Try to complete checkout"
3. Observe: Don't help, watch for struggles
4. Ask: "What were you thinking?"
5. Analyze: Where did they struggle?

**Metrics**:

- Task completion rate
- Time on task
- Error count
- Satisfaction rating

### Method 3: Analytics Review (Quantitative)

**Best for**: Understanding aggregate behavior

**Key metrics**:

- Funnel drop-off: Where do users leave?
- Feature usage: What features are popular?
- User journey: What's the path?
- Error rates: Where do errors happen?

### Method 4: A/B Testing (Quantitative)

**Best for**: Comparing approaches

**Process**:

1. Identify hypothesis: "Blue button = more clicks"
2. Create variant: Button color changed
3. Split traffic: 50% to each version
4. Measure: Count clicks
5. Analyze: Which is better?

## Analysis & Insights

### Thematic Analysis

```
Session 1: "The form is too long"
Session 2: "I didn't know which field was required"
Session 3: "The form is confusing"

Theme: Clarity issues with form
Insight: Users need clear guidance on form requirements
```

### Affinity Mapping

```
Create cards for each observation
Group related observations
Find themes
Prioritize issues
```

## Common Testing Patterns

### Pattern: Moderated Testing (Researcher present)

**Advantages**: Can ask follow-up questions
**Disadvantages**: Research presence may bias behavior

### Pattern: Unmoderated Testing (User alone)

**Advantages**: Natural behavior
**Disadvantages**: Can't follow up

### Pattern: Remote Testing (Online)

**Advantages**: Geographic reach, lower cost
**Disadvantages**: Technical issues, less rapport

## Communicating Results

**Research Report Structure**:

1. Research question
2. Methodology (who, how many, how)
3. Key findings (3-5 main insights)
4. Detailed evidence (quotes, videos, data)
5. Recommendations (actionable next steps)
6. Appendix (full data, consent forms)

**Tips**:

- Lead with insights, not methods
- Show video clips of user confusion
- Quote users directly
- Provide actionable recommendations
- Share surprising findings

---

## Stakeholder Management

**Managing Disagreement**:

- Bring data: "3 of 5 users missed this"
- Use quotes: "Users said it's confusing"
- Show video: Watch user struggle
- Respect tradeoffs: Understand constraints
- Prioritize: What matters most?

## Ethical Considerations

- Informed consent: Users know they're observed
- Privacy: Don't share identifying information
- Compensation: Pay for time
- Respect: Don't manipulate
- Transparency: Share findings honestly
