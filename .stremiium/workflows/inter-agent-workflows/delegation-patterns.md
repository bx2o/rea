# Delegation Patterns - Inter-Agent Coordination Framework

**Purpose**: Guidelines for delegating tasks between agents  
**Audience**: All agents managing work  
**Last Updated**: February 18, 2026

---

## Overview

Effective delegation is the backbone of multi-agent operation. This document provides patterns for how Sparkling Curious delegates work across the 10 main agents and 21 subagents, ensuring clear ownership, accountability, and successful outcomes.

---

## Multi-Council Delegation Principles (16 Councils)

### 1. Clarity with Council Context

**Every delegation must include**:

- Clear objective and desired outcome
- Affected councils (primary + secondary)
- Cross-council dependencies and blockers
- Timeline and deadlines with council SLAs
- Decision authority levels (Council Captain > Sparkling Curious)
- Escalation criteria and routing

### 2. Capability Matching

**Match the task to the right agent**:

- Consider primary expertise
- Evaluate current workload
- Identify skill gaps
- Consider development opportunities

### 3. Communication

**Ensure understanding**:

- Confirm receipt and understanding
- Answer questions upfront
- Provide necessary context
- Make self available for questions

### 4. Accountability

**Clear ownership**:

- One primary agent responsible
- Named backup if needed
- Clear success criteria
- Regular check-ins

### 5. Support

**Enable success**:

- Remove obstacles early
- Provide necessary resources
- Connect with supporting agents
- Monitor progress

## Delegation Patterns by Situation

### Pattern 1: Core Responsibility Delegation

**When**: Delegating work that is primary responsibility of that agent

**Example**: Delegating architecture design to The Architect

**Key Points**:

- Agent has full authority
- Minimal check-ins needed
- Agent defines their own approach
- Quick approval/support

**Workflow**:

1. Provide clear objective
2. Clarify constraints and timeline
3. Agent takes ownership
4. Scheduled check-in at midpoint
5. Final review/approval at end

**Expected Duration**: Per agent's normal timeline

---

### Pattern 2: Cross-Functional Delegation

**When**: Task requires coordination across multiple agents

**Example**: New product launch requiring marketing, sales, product, engineering

**Key Points**:

- One primary lead agent
- Supporting agents have specific roles
- Coordination meetings required
- Clear decision-making authority
- Conflict resolution process

**Workflow**:

1. Assign lead agent
2. Identify supporting agents
3. Create project coordination structure
4. Schedule kickoff meeting
5. Weekly coordination meetings
6. Monthly steering meetings
7. Final integration review

**Expected Duration**: Project-dependent (weeks/months)

---

### Pattern 3: Specialist Delegation

**When**: Task requires specific subagent expertise

**Example**: Conflict resolution through The Mediator (subagent of The Guardian)

**Key Points**:

- Specific specialized skill needed
- May be time-sensitive
- Clear scope (often limited)
- Defined deliverable
- Quick turnaround

**Workflow**:

1. Identify specific specialist needed
2. Brief them on situation
3. Provide authority to act
4. Check in at key points
5. Summarize and act on results

**Expected Duration**: Hours to days

---

### Pattern 4: Development Delegation

**When**: Delegating to stretch agent capabilities

**Example**: New technical domain for team member

**Key Points**:

- Provide mentoring support
- Allow extra time for learning
- Regular check-ins
- Plan for knowledge sharing
- Build confidence gradually

**Workflow**:

1. Discuss learning opportunity
2. Provide learning resources
3. Start with smaller task
4. Pair/mentor during execution
5. Regular feedback
6. Reflect on learning
7. Apply to larger work

**Expected Duration**: Longer than standard (add 30-50%)

---

### Pattern 5: Crisis Delegation

**When**: Urgent issue requires immediate action

**Example**: Security incident response, production outage

**Key Points**:

- Clear authority to act immediately
- Minimal approval process
- Focus on crisis mitigation
- Decision-making by agent
- Communication paramount

**Workflow**:

1. Clear crisis designation
2. Full emergency authority
3. 15-minute updates initially
4. Escalation only if blocked
5. Post-crisis review

**Expected Duration**: As long as needed, 24/7 response

## Effective Handoff Process

### Before Delegation (Planning)

- [ ] Clarify objective with requesting party
- [ ] Identify resource needs
- [ ] Assess timeline and urgency
- [ ] Review agent capacity
- [ ] Get approvals if needed

### During Handoff (Kickoff)

- [ ] Schedule dedicated handoff meeting
- [ ] Walk through objective and constraints
- [ ] Review success criteria together
- [ ] Answer all questions
- [ ] Confirm understanding
- [ ] Establish check-in schedule

### During Execution (Support)

- [ ] Scheduled check-ins per plan
- [ ] Remove obstacles early
- [ ] Connect with supporting agents
- [ ] Adjust if circumstances change
- [ ] Provide encouragement and support

### At Completion (Closure)

- [ ] Review completed work
- [ ] Verify against success criteria
- [ ] Capture lessons learned
- [ ] Thank the agent
- [ ] Use results/feedback in next planning

## Common Pitfalls to Avoid

### Pitfall 1: Unclear Objectives

**Problem**: Agent confused about what "done" looks like  
**Solution**: Use SMART criteria (Specific, Measurable, Achievable, Relevant, Time-bound)

### Pitfall 2: Over-Delegation

**Problem**: Agent drowning in work, everything gets delayed  
**Solution**: Monitor workload, use backup agents, delay non-critical work

### Pitfall 3: Under-Support

**Problem**: Agent stuck on obstacle, can't make progress  
**Solution**: Regular check-ins, clear escalation path, pro-active support

### Pitfall 4: Unclear Authority

**Problem**: Agent uncertain what they can decide independently  
**Solution**: Explicitly define decision authority levels upfront

### Pitfall 5: No Accountability

**Problem**: Task falls through cracks, nobody takes responsibility  
**Solution**: Clear single owner, backup designated, escalation to Sparkling Curious if needed

## Monitoring Delegation Success

### Key Metrics

- **On-Time Completion**: Percentage of delegated tasks completed on schedule
- **Quality**: Percentage meeting success criteria on first completion
- **Satisfaction**: Agent satisfaction with delegation clarity
- **Issues**: Number of escalations, blocked items
- **Learning**: Skills developed through delegated work

### Regular Reviews

**Weekly**: Ongoing delegation tracking and support  
**Monthly**: Delegation effectiveness assessment  
**Quarterly**: Patterns and process improvement

## When to Re-Delegate

### Circumstances Requiring Re-delegation

- Original agent unavailable
- Scope changed significantly
- Complexity greater than anticipated
- Capability not matching requirement
- Priority change making original assignment invalid

### Re-delegation Process

1. Communicate change to current owner
2. Ensure smooth transition
3. Provide new owner with context
4. Update timeline/deadlines
5. Clear current owner from responsibility
6. Document reason for change
