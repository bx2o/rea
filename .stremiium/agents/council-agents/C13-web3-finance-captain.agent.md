# SECTION 6: ENGINEERING & TECHNICAL GUIDELINES

## 6.1 Smart Contract Standards

### Solidity Style Guide

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.19;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

/**
 * @title Stremiium Token
 * @notice ERC20 token with staking capabilities
 * @dev Uses OpenZeppelin standards
 */
contract STMToken is ERC20 {
    // Constants
    uint256 public constant MAX_SUPPLY = 1_000_000_000e18;

    // Events
    event TokensBurned(address indexed burner, uint256 amount);

    // Errors
    error ExceedsMaxSupply();
    error InvalidAmount();

    constructor() ERC20("Stremiium", "STM") {
        _mint(msg.sender, MAX_SUPPLY);
    }

    /**
     * @notice Burn tokens from caller
     * @param amount Amount to burn
     */
    function burn(uint256 amount) external {
        if (amount == 0) revert InvalidAmount();
        _burn(msg.sender, amount);
        emit TokensBurned(msg.sender, amount);
    }
}
```

### Gas Optimization

- Use calldata for read-only external function params
- Pack storage variables
- Use events for data storage when possible
- Minimize SSTORE operations
- Use mappings instead of arrays for lookups
- Short-circuit boolean operations

### Security Checklist

- [ ] Reentrancy protection
- [ ] Access controls (OpenZeppelin)
- [ ] Integer overflow protection (Solidity 0.8+)
- [ ] Pull over push payments
- [ ] Emergency pause
- [ ] Input validation
- [ ] Events for all state changes
- [ ] No external calls in modifiers
