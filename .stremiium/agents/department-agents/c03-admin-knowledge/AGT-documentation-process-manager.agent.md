# SECTION 4: KEY FAQS & KNOWLEDGE LIBRARY

## 4.1 Frequently Asked Questions

**Q1: How do you document a process that no one fully understands?**
A: Approach: (1) **Map the fragments** - Each person knows part. (2) **Assemble end-to-end** - Connect the pieces. (3) **Validate with all** - Does this match reality? (4) **Identify gaps** - What's missing or unclear? (5) **Test and refine** - Walk through with actual work. (6) **Document decisions** - Note where process was ambiguous and you made choices.

**Q2: What's the difference between a process map and an SOP?**
A: **Process Map** = visual overview (the "what" and flow). Shows steps, decision points, handoffs, timelines. Good for understanding the big picture. **SOP** = detailed instructions (the "how"). Shows exact steps, responsible party, tools needed, inputs/outputs. Good for executing. Use both: Map for understanding, SOP for doing.

**Q3: How detailed should SOPs be?**
A: Guideline: Document what a competent person needs to succeed without asking questions. Too vague = confusion and variation. Too detailed = maintenance burden and people skip reading. Test: Can someone follow it without help? If yes, detailed enough. If no, add clarity.

**Q4: How do you identify automation opportunities?**
A: Assessment criteria: (1) **Volume** - High transaction counts. (2) **Rules-based** - Clear logic, few exceptions. (3) **Structured data** - Digital inputs. (4) **Stable** - Process doesn't change frequently. (5) **Error-prone** - Manual mistakes common. (6) **ROI positive** - Automation cost < savings.

**Q5: How do you get process owners to follow documented procedures?**
A: Strategy: (1) **Involve them in creation** - People follow what they helped build. (2) **Make it easier** - SOP should reduce effort. (3) **Show value** - "This reduces errors/approvals." (4) **Management support** - Leaders enforce compliance. (5) **Measure and report** - Visibility drives accountability.

**Q6: How often should process documentation be reviewed?**
A: Schedule: **Annual** for all critical processes (minimum). **Quarterly** for high-change areas. **Trigger-based** when process changes, errors occur, new tools deployed, or audit findings highlight gaps.

**Q7: What's the best format for process documentation?**
A: **Visual maps** for understanding flow. **Written SOPs** for detailed execution. **Videos** for complex procedures. **Checklists** for verification. **Quick reference cards** for frequent tasks. Best practice: Visual map + detailed SOP linked together.

**Q8: How do you handle process variations?**
A: Options: **Variant SOPs** for major variations. **Decision trees** with clear if/then branches. **Modular design** with common steps + variant modules. Document decision criteria clearly.

# SECTION 5: SOPs (STANDARD OPERATING PROCEDURES)

## 5.1 SOP 1: Process Documentation Development

**Duration:** 1-2 weeks | **Frequency:** Per process

1. **Scoping:** Define process boundaries and objectives
2. **Information gathering:** Interviews, observation, document review
3. **Process mapping:** Create visual flow of current state
4. **SOP drafting:** Write detailed procedure
5. **Validation:** Review with process owners and users
6. **Approval:** Sign-off from stakeholders
7. **Publication:** Release to procedure library
8. **Training:** Enable adoption
9. **Review schedule:** Set review triggers

## 5.2 SOP 2: Process Improvement Initiative

**Duration:** 4-8 weeks | **Frequency:** As needed

1. **Process selection:** Prioritize based on pain points/volume
2. **Current state analysis:** Document as-is process
3. **Problem identification:** Find waste, bottlenecks, errors
4. **Root cause analysis:** 5 Whys, fishbone diagram
5. **Solution design:** Develop to-be process
6. **Business case:** Quantify benefits and costs
7. **Approval:** Stakeholder buy-in
8. **Implementation:** Deploy changes
9. **Monitoring:** Track improvement metrics
10. **Standardization:** Update documentation

## 5.3 SOP 3: Annual Process Documentation Audit

**Duration:** 2-3 days | **Frequency:** Annually

1. **Inventory:** List all documented processes
2. **Coverage assessment:** Identify undocumented critical processes
3. **Accuracy check:** Verify procedures match actual practice
4. **Usage analysis:** Identify unused/outdated documentation
5. **Gap analysis:** Document missing procedures
6. **Update prioritization:** Rank by criticality
7. **Plan development:** Create update roadmap
8. **Execution:** Update high-priority items
9. **Reporting:** Communicate status to stakeholders

## 6.3 Value Stream Analysis Framework

1. **Customer value:** What does the customer pay for?
2. **Value-add steps:** Directly create customer value
3. **Non-value-add (necessary):** Required overhead
4. **Non-value-add (waste):** Eliminate if possible
5. **Flow efficiency:** Value-add time / Total time
6. **Improvement target:** Reduce waste, increase flow
