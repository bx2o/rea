# SECTION 4: FIFTY+ FAQS, SKILLS & KNOWLEDGE LIBRARY

## 4.1 Fifty+ Frequently Asked Questions (FAQs)

### **Category 1: DOCUMENTATION STANDARDS (14 FAQs)**

**Q1: What should a documentation style guide include?**
A: Contents: (1) **Writing style:** Tone (professional? casual?), active vs. passive voice, clarity guidelines. (2) **Formatting:** Headings, bold, italics, lists, code blocks. (3) **Structure:** How to organize documents (intro, body, conclusion). (4) **Terminology:** Consistent terms (don't call feature X in one doc, Y in another). (5) **Examples:** Good examples of compliant docs. (6) **Checklists:** Pre-publication checklist. (7) **Tools:** What tools for writing? (Google Docs? Word? Markdown?). (8) **Templates:** Templates for different doc types. Length: 5-20 pages. Use: Every document should follow guide.

**Q2: What's a documentation template and how do you create one?**
A: Template: Pre-formatted document with structure and placeholders. Purpose: Consistency + faster creation. Types: Process doc template, meeting notes template, decision doc template, policy template. Contents: (1) **Header:** Title, author, date, status. (2) **Purpose:** Why this document? (3) **Audience:** Who's reading? (4) **Structure:** Sections with placeholders. (5) **Examples:** Show what good looks like. Creation: (1) Pick existing good docs. (2) Extract common structure. (3) Create template with placeholders. (4) Test with users (does it work?). (5) Refine based on feedback. Value: Saves time + ensures consistency.

**Q3: How do you test documentation for clarity?**
A: Testing: (1) **Read aloud:** Does it sound clear? (2) **Readability score:** Use tools (Flesch-Kincaid) to measure readability. Aim: 8th-grade reading level. (3) **User testing:** Have people unfamiliar with content try to use it. Can they understand? (4) **Jargon check:** Did you use unexplained jargon? (5) **Step-by-step:** If process doc, can someone follow steps exactly? (6) **Ambiguity:** Are there multiple interpretations? (7) **Length:** Is it unnecessarily long? (8) **Examples:** Do examples help clarify? Process: Write → Test → Revise → Retest. Goal: 90%+ of users understand on first read.

**Q4: What's a document review and approval process?**
A: Process: (1) **Draft:** Author writes document. (2) **Self-review:** Author reviews for quality. (3) **Peer review:** Colleague reviews for clarity, accuracy. (4) **Subject matter expert review:** Expert verifies accuracy. (5) **Legal review:** If legal implications, legal reviews. (6) **Leadership approval:** Final approval from leader accountable for doc. (7) **Publish:** Document published to knowledge base. (8) **Communicate:** Team notified of new/updated doc. Timeline: 2-4 weeks typical. Complexity: Varies (policy = more complex; process = simpler).

**Q5: How do you maintain version control for documents?**
A: Version control: (1) **Naming:** Include version number in filename (v1.0, v1.1, v2.0). (2) **Change log:** Note what changed in each version. (3) **History:** Keep versions (so can reference old versions if needed). (4) **Archive:** Old versions archived (not deleted). (5) **Dates:** Include publication date. (6) **Status:** Draft vs. final (avoid confusion). (7) **Author:** Track who created/updated. (8) **Tools:** Use tools with version control (Google Docs, Confluence, Git). Best practice: Semantic versioning (major.minor.patch).

**Q6: How do you ensure 100% employee acknowledgment of policies?**
A: Process: (1) **Digital acknowledgment:** Employees sign off digitally (acknowledge receipt + understanding). (2) **Reminder system:** Send reminders (annual, or when policy changes). (3) **Tracking:** HR system tracks who acknowledged. (4) **Non-acknowledgment follow-up:** Manager follows up with non-compliant employees. (5) **Termination requirement:** Can't hire without acknowledgment. (6) **Refusal handling:** If employee refuses, escalate (usually termination-eligible). (7) **Record keeping:** Keep signed acknowledgments (2+ years). Tools: HR system, acknowledgment tool (DocuSign, etc.). Goal: 100% acknowledgment documented.

**Q7: What policies should every company have?**
A: Core policies: (1) **Handbook:** Overview of company, employment relationship. (2) **Code of conduct:** Expected behavior, ethics. (3) **Confidentiality:** How to handle secrets. (4) **Remote work:** If applicable, work-from-home rules. (5) **Harassment/discrimination:** Prevention, reporting. (6) **Safety:** Physical safety, driving safety, etc. (7) **Benefits:** Health insurance, PTO, retirement. (8) **Time off:** Vacation, sick time, parental leave. (9) **Expense reimbursement:** What can be reimbursed, process. (10) **Social media:** Company social media standards. (11) **Data security:** How to handle data. (12) **Acceptable use:** Computer/internet acceptable use. Add: As business grows, add policies for specific situations.

**Q8: How do you measure documentation quality?**
A: Metrics: (1) **Readability score:** Flesch-Kincaid score (target: 8th-grade level). (2) **Completeness:** % of required sections included. (3) **Accuracy:** If reviewed by expert, % accurate. (4) **Consistency:** Does it follow style guide? (5) **Clarity:** % of test readers who understood. (6) **Usefulness:** Do employees find it helpful? (7) **Freshness:** When was last updated? (8) **Coverage:** % of processes documented? Scoring: Create rubric (1-5 scale for each dimension). Target: 4+ average.

**Q9: What's document retention and why does it matter?**
A: Retention: How long to keep documents. Matters: (1) **Legal**: Some docs required 3-7 years (tax, employment, contracts). (2) **Compliance:** Regulators may require retention. (3) **Risk:** Old docs create clutter/confusion. (4) **Privacy:** Some docs should be destroyed (PII, secrets). Schedule: Create retention schedule (different docs, different periods). Examples: Employee files (7+ years post-termination), financial (7 years), contracts (life + 3 years). Archival: Old docs archived (not deleted), accessible if needed. Destruction: When retention period expires, securely destroy. Policy: Document retention policy with schedule.

**Q10: How do you handle document updates without creating confusion?**
A: Challenge: Update document → People still using old version. Solutions: (1) **Version control:** Clear versioning (v1.0 vs. v2.0). (2) **Notification:** Notify team when doc updates. (3) **Deprecated notation:** Mark old versions "deprecated" or "archived". (4) **Redirection:** Old doc links to new version. (5) **Changelog:** Explain what changed. (6) **Training:** If significant change, conduct training. (7) **Phased rollout:** For major changes, give people time to transition. (8) **Archive old version:** Keep in case someone needs history. Best practice: Clear versioning + notification = avoids confusion.
