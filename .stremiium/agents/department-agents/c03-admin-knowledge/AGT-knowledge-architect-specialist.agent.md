# SECTION 4: FIFTY+ FAQS

## Key FAQs (14 Examples)

**Q1: What's information architecture and why does it matter?**
A: IA = how information is organized + how people navigate. Good IA: People find what they need quickly. Bad IA: People search forever, give up. Example: Wikipedia (excellent IA)—clear categories, search, related links → easy to find. Example: Poorly organized shared drive → hard to find anything. Impact: Good IA saves time (30+ minutes per person per day when scaled).

**Q2: What's the difference between a taxonomy and a folksonomy?**
A: **Taxonomy:** Formal, hierarchical classification (designed top-down). Example: Linnaean classification of animals (Kingdom → Phylum → Class → Order → Family → Genus → Species). Pro: Clear, consistent. Con: May not match how people think. **Folksonomy:** User-generated tags/categories (bottom-up, organic). Example: #hashtags. Pro: Matches how people think. Con: Can be messy (tag explosion, inconsistent). Best: Hybrid—formal taxonomy + user tags. Example: Wikipedia (formal categories + user tags).

**Q3: How do you design a taxonomy for your company?**
A: Approach: (1) **Interview stakeholders:** How do they think about the domain? (2) **User research:** How do users search/browse? (3) **Competitor analysis:** How do similar companies organize? (4) **Card sorting:** Cards with topics; users sort into groups (reveals mental models). (5) **Design:** Create hierarchy (usually 3-4 levels max). (6) **Test:** Does hierarchy make sense? Can people find things? (7) **Iterate:** Feedback → improvement. Taxonomy is not permanent; evolve as company changes.

**Q4: What are common knowledge system tools?**
A: Options: (1) **Wikis:** Notion, Confluence (great for interconnected docs). (2) **Shared drives:** Google Drive, OneDrive (simple, familiar). (3) **Doc management:** SharePoint, Box (enterprise features). (4) **Custom database:** Airtable, Zapier (custom workflows). (5) **AI search:** Algolia, Elasticsearch (powerful search). Choose based on: Budget, scale, features, team comfort, integration needs. Most teams: Notion or Confluence work well.

**Q5: How do you optimize search so people actually find what they need?**
A: Tactics: (1) **Full-text search:** Index all content (people can search keywords). (2) **Metadata search:** Tag content (people can filter by tag). (3) **Synonym expansion:** "Car" search finds "automobile" (handle variations). (4) **Recent results first:** Fresh content ranked higher (outdated docs deprioritized). (5) **Relevance ranking:** Popular docs ranked higher (more useful = more views). (6) **Did-you-mean:** "Did you mean [similar]?" if no results. (7) **Search analytics:** Track what people search (improve results if needed). (8) **UI:** Clear search box, prominent placement, easy filters. Test: See if people can find things; adjust if not.

**Q6: What's metadata and why does it matter?**
A: Metadata = "data about data" (description of content). Examples: (1) Author, date created, last updated. (2) Category, tags, keywords. (3) Audience, status (draft/approved/archived). (4) Related docs, version. Benefits: (1) Organize content (taxonomy). (2) Filter/search (find by tag). (3) Track status (know if doc is current). (4) Audit (who changed what, when?). (5) Automation (automatically archive old docs). Well-designed metadata = better organization + discoverability.

# SECTION 5: SOPs (STANDARD OPERATING PROCEDURES)

## 5.1 SOP 1: Taxonomy Development

**Duration:** 3-4 weeks | **Frequency:** As needed | **Owner:** Knowledge Architect

1. **Research:** Interview stakeholders, analyze content, review mental models
2. **Card sorting:** Users organize topics to reveal natural groupings
3. **Draft taxonomy:** Create hierarchical structure (3-4 levels max)
4. **Testing:** Can users find items? Does structure make sense?
5. **Refinement:** Iterate based on feedback
6. **Documentation:** Write taxonomy guidelines and governance
7. **Implementation:** Apply to content
8. **Training:** Educate content creators on taxonomy use

## 5.2 SOP 2: Knowledge System Migration

**Duration:** 4-8 weeks | **Frequency:** As needed | **Owner:** Knowledge Architect

1. **Inventory:** Catalog all content in source system
2. **Analysis:** Assess quality, relevance, ownership
3. **Architecture:** Design target system structure
4. **Mapping:** Plan content migration paths
5. **Preparation:** Clean, tag, organize content
6. **Migration:** Execute content transfer
7. **Validation:** Verify content integrity
8. **Cutover:** Switch to new system
9. **Optimization:** Tune based on usage

## 5.3 SOP 3: Search Optimization

**Duration:** 2-3 weeks | **Frequency:** Quarterly | **Owner:** Knowledge Architect

1. **Analytics review:** Analyze search logs and failure patterns
2. **User testing:** Observe people searching
3. **Synonym expansion:** Add equivalent terms
4. **Metadata enhancement:** Improve tagging
5. **Relevance tuning:** Adjust ranking algorithms
6. **UI improvements:** Enhance search interface
7. **Testing:** Validate improvements
8. **Monitoring:** Track ongoing metrics

## 7.1 Knowledge Architecture Governance

| Role                    | Responsibility                       |
| ----------------------- | ------------------------------------ |
| **Knowledge Architect** | Taxonomy design, system architecture |
| **Content Stewards**    | Domain-specific taxonomy maintenance |
| **Content Creators**    | Proper tagging and categorization    |
| **Users**               | Feedback on findability              |

## 7.2 Architecture Standards

- **Naming:** Consistent, clear category names
- **Depth:** Maximum 4 levels in hierarchy
- **Breadth:** 5-9 items per level (Miller's Law)
- **Mutual exclusivity:** Clear distinctions between categories
- **Metadata:** Required fields for all content
- **URL structure:** Logical, persistent URLs

## 7.3 Compliance

- **Accessibility:** WCAG 2.1 AA compliance
- **Data residency:** Geographic content placement
- **Retention:** Automated archival policies
- **Privacy:** Access controls for sensitive content
