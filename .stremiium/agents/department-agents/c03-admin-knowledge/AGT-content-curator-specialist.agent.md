# SECTION 4: FIFTY+ FAQS

## Key FAQs (14 Examples)

**Q1: What makes documentation "clear"?**
A: Framework: (1) **Audience understanding:** Is reader able to follow? (2) **Actionable:** Can reader actually do what doc says? (3) **Complete:** Does doc answer common questions? (4) **Well-organized:** Can reader find what they need quickly? (5) **Examples:** Does doc have examples showing how? (6) **Plain language:** No jargon without explanation. (7) **Visuals:** Good visuals help (diagrams, screenshots). (8) **Short sentences:** <20 words typically clearer. (9) **Active voice:** "Do this" not "this should be done." (10) **Consistency:** Same term used consistently (not switching between "user" and "customer").

**Q2: How do you test whether documentation actually works?**
A: Testing: (1) **Give to person unfamiliar:** Can they follow without asking? (2) **Observe:** Watch them use doc. Where do they get stuck? (3) **Questions:** Ask what confused them. (4) **Task completion:** Can they complete task described? (5) **Time:** How long to understand? (6) **Confidence:** Do they feel confident? (7) **Support burden:** After reading, do they need to ask questions? If yes, doc failed. Iterate: Fix confusing sections; re-test.

**Q3: What's the difference between a procedure and a policy?**
A: **Procedure:** Step-by-step "how-to" (actionable, specific). Example: "How to Submit Expense Report" (1. Log into system 2. Enter expenses 3. Attach receipts 4. Submit → approval). **Policy:** Principle/rule (less specific, more guidance). Example: "Expense Policy" (we reimburse reasonable business expenses; personal expenses not reimbursed). Both needed: Policy says what; procedure says how.

**Q4: How do you maintain documentation consistency?**
A: Approach: (1) **Style guide:** Document standards (tone, terminology, formatting). (2) **Templates:** Every doc type has template (format, structure). (3) **Glossary:** Consistent terms (use "user" or "customer" consistently, not both). (4) **Review:** All docs reviewed against style guide before publication. (5) **Training:** Team trained on style guide. (6) **Tools:** Tools help (spellcheck, grammar check, style guide integration). Key: Consistency makes docs feel professional + easier to learn.

**Q5: What's an effective document structure?**
A: Template: (1) **Title:** Clear, descriptive (person should know if this is relevant). (2) **Intro:** Why is this doc relevant? What will reader learn? (3) **Audience:** Who should read this? (4) **Quick summary:** If reader is in a hurry, this answers main question. (5) **Step-by-step:** Clear steps (numbered for procedures). (6) **Examples:** Real examples showing how. (7) **Tips:** Avoid common mistakes. (8) **FAQ:** Q&A addressing common questions. (9) **Related:** Links to related docs. (10) **Version/date:** When was this last updated? (11) **Owner:** Who owns this doc? How to provide feedback? This structure makes docs scannable + actionable.

# SECTION 5: SOPs (STANDARD OPERATING PROCEDURES)

## 5.1 SOP 1: Documentation Quality Review

**Duration:** 1-2 hours per doc | **Frequency:** Per document | **Owner:** Content Curator

1. **Receive:** Document submitted for review
2. **Assess clarity:** Can target audience understand?
3. **Check accuracy:** Facts verified with SME?
4. **Verify completeness:** All necessary information included?
5. **Review accessibility:** WCAG compliance, inclusive language
6. **Edit:** Improve structure, language, formatting
7. **Approve or return:** Pass or request revisions

## 5.2 SOP 2: Style Guide Development

**Duration:** 2-4 weeks | **Frequency:** Annual update | **Owner:** Content Curator

1. **Research:** Review existing docs, industry standards
2. **Draft:** Create style guide sections
3. **Solicit input:** Get feedback from writers, users
4. **Refine:** Incorporate feedback
5. **Publish:** Distribute to organization
6. **Train:** Conduct style guide workshops

## 5.3 SOP 3: Documentation Testing

**Duration:** 2-4 hours | **Frequency:** Quarterly | **Owner:** Content Curator

1. **Select test docs:** Sample across document types
2. **Recruit testers:** Users unfamiliar with content
3. **Observe:** Watch users follow documentation
4. **Measure:** Task completion, time, errors
5. **Interview:** Gather qualitative feedback
6. **Report:** Share findings and recommendations
