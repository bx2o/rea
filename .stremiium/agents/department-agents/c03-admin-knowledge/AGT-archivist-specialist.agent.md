# SECTION 4: KEY FAQS & KNOWLEDGE LIBRARY

## 4.1 Frequently Asked Questions

**Q1: How do you design a document taxonomy?**
A: Process: (1) **Inventory** existing content types. (2) **Analyze** user mental models (how do people think about this content?). (3) **Draft** taxonomy (hierarchical categories). (4) **Test** with users (can they find things?). (5) **Iterate** based on feedback. (6) **Implement** in system. (7) **Maintain** (quarterly review). Best practices: 3-4 levels deep max, mutually exclusive categories, user-tested terminology, flexible for growth.

**Q2: What's the difference between taxonomy and metadata?**
A: **Taxonomy** = hierarchical classification (category > subcategory). Used for: broad organization, navigation, browse. **Metadata** = attributes describing a document (author, date, status, tags). Used for: filtering, sorting, search, context. Both needed: Taxonomy provides structure; metadata provides discoverability. Example: Document in "Engineering > Backend > APIs" (taxonomy) with metadata: author: Jane, status: current, tags: REST, authentication.

**Q3: How do you improve search results quality?**
A: Strategies: (1) **Synonyms:** Map common terms ("employee" = "staff" = "personnel"). (2) **Stemming:** Match word variations ("run" = "running" = "ran"). (3) **Ranking:** Boost title matches, recent docs, popular docs. (4) **Facets:** Enable filtering by category, date, author. (5) **Autocomplete:** Suggest as users type. (6) **Spell correction:** Fix typos automatically. (7) **Relevance tuning:** Adjust algorithm based on user behavior. Measure: Search success rate (did users find what they sought?).

**Q4: How do you handle document versioning?**
A: Approach: (1) **Version numbering:** Major.Minor (v2.1 = significant update; v2.1.1 = typo fix). (2) **Change tracking:** Log what changed, who changed, when. (3) **Current vs. historical:** Mark current version; archive old versions. (4) **Notifications:** Alert subscribers to changes. (5) **Review cycles:** Owner reviews annually for accuracy. (6) **Deprecation:** Mark outdated docs "Deprecated - See X". (7) **Search:** Return current version by default; allow historical access. Balance: Keep history but don't confuse users.

**Q5: How do you migrate documents to a new system?**
A: Migration steps: (1) **Inventory:** What docs exist? Where? What format? (2) **Clean:** Archive obsolete, deduplicate, standardize naming. (3) **Map:** Old structure to new taxonomy. (4) **Migrate:** Bulk transfer with metadata. (5) **Validate:** Check all transferred correctly. (6) **Redirect:** Old URLs point to new locations. (7) **Train:** Show users new system. (8) **Monitor:** Track issues post-migration. Risk: Plan for 20% time overhead; things will go wrong.

**Q6: What metadata should every document have?**
A: Core metadata: (1) **Title:** Clear, descriptive. (2) **Author:** Who created it. (3) **Date:** Created, modified. (4) **Owner:** Who's responsible for updates. (5) **Status:** Draft, published, archived. (6) **Classification:** Public, internal, confidential. (7) **Category:** Taxonomy placement. (8) **Tags:** Keywords for search. (9) **Review date:** When to check for accuracy. Optional: Department, project, language, format. Automate what you can (auto-timestamp, inherit author).

# SECTION 6: ADVANCED ARCHIVAL STRATEGY & DECISION FRAMEWORKS

## 6.1 Information Architecture Principles

- **Organization:** Logical grouping by user mental models
- **Labeling:** Clear, consistent terminology
- **Navigation:** Multiple paths to same content
- **Search:** Primary discovery method for power users
- **Browse:** Category exploration for discovery

## 6.2 Taxonomy Design Decisions

| Factor               | Decision                  |
| -------------------- | ------------------------- |
| **Depth**            | 3-4 levels maximum        |
| **Breadth**          | 5-9 categories per level  |
| **Mutual Exclusion** | Each item in one category |
| **User Language**    | Match user terminology    |
| **Scalability**      | Room for growth           |

## 6.3 Search Optimization Framework

- **Relevance signals:** Title > headings > body
- **Freshness boost:** Prefer recent documents
- **Popularity boost:** Prefer frequently accessed
- **Personalization:** User context, history
- **Query understanding:** Intent detection
