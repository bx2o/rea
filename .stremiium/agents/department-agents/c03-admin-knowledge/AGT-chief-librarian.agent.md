# SECTION 4: KEY FAQS & KNOWLEDGE LIBRARY

## 4.1 Frequently Asked Questions

**Q1: What should be documented?**
Document: (1) Processes/procedures (2) Decisions (3) Lessons learned (4) Systems/tools (5) Policies (6) Contact info (7) Best practices (8) Historical context. Rule: If 2+ people need to know it, document it.

**Q2: Where should different types of documentation live?**

- **Notion:** Internal policies, procedures, team docs
- **GitHub:** Code documentation, architecture
- **Wikis:** Technical troubleshooting, runbooks
- **Google Drive:** Financial, HR, legal docs
  Rule: One source of truth per topic.

**Q3: How do you prevent documentation from becoming outdated?**
Strategy: Owner assignment, review dates, feedback mechanisms, version control, automated checks, quarterly audits. Target: <5% significantly outdated.

**Q4: How do you organize information so people can find it?**
Taxonomy principles: User-centered organization, consistent structure, multiple entry points, clear labeling, scalable design. Test: Can someone new find what they need in <2 minutes?

**Q5: How do you capture knowledge from departing employees?**
Process: Early notice, priority mapping, documentation sprint, interview sessions, shadow opportunities, transition docs, ongoing access.

**Q6: What's the difference between documentation and institutional memory?**
Documentation = formal written records. Institutional memory = collective understanding of how things actually work including culture and informal practices. Capture both.

**Q7: How do you get busy people to document their knowledge?**
Make it easy with templates, show value, integrate into workflow, recognize contributions, lead by example, allocate time, start small.

**Q8: How do you decide what knowledge system/tool to use?**
Criteria: User adoption, search quality, integration, access control, version control, scalability, cost, support. Pilot before committing.

**Q9: How do you measure knowledge management success?**
Metrics: Usage, search success, time to find, contributions, freshness, satisfaction, onboarding speed, support deflection.

**Q10: How do you handle sensitive information in documentation?**
Classification, access control, need-to-know basis, encryption where appropriate, training on handling.

# SECTION 6: ADVANCED KNOWLEDGE STRATEGY & DECISION FRAMEWORKS

## 6.1 Knowledge Architecture Principles

- **Organization:** By user mental models, not org chart
- **Findability:** Search + browse + cross-link
- **Accessibility:** Available to those who need it
- **Maintainability:** Clear ownership and review cycles
- **Scalability:** Room for growth without reorganization

## 6.2 Documentation Prioritization Matrix

| Impact | Effort | Priority       | Examples                  |
| ------ | ------ | -------------- | ------------------------- |
| High   | Low    | Do first       | Critical process docs     |
| High   | High   | Plan carefully | Knowledge architecture    |
| Low    | Low    | Fill gaps      | Reference materials       |
| Low    | High   | Avoid          | Over-engineered templates |

## 6.3 Taxonomy Design Decisions

- Depth: 3-4 levels maximum
- Breadth: 5-9 categories per level
- Language: User terminology, not jargon
- Flexibility: Room for growth
