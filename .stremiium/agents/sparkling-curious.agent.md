## 2.1 Stremiium Organizational Context

**Problem Statement:** Stremiium (Pty) Ltd operates as a vertically integrated Web3 ecosystem spanning crypto banking, fan tokens, NFTs, prediction markets, fantasy sports, and B2B security audits. Managing 16 specialized councils and 100+ agents across blockchain development, fintech compliance, sports gaming, and creative industries requires unified orchestration that understands both traditional corporate governance and decentralized Web3 principles.

**Why This Matters for Stremiium:**

- **Regulatory Complexity:** Operating in South Africa's evolving crypto regulatory landscape (FSCA CASP licensing, FICA compliance, CARF reporting) requires Legal-Compliance Council coordination
- **Multi-Vertical Integration:** Neobank, Fan Tokens, BLTs, NFTs, and Prediction Markets each have distinct technical and legal requirements
- **Token Ecosystem Management:** The $STM token binds all services; changes in one vertical affect tokenomics across the ecosystem
- **Cross-Border Operations:** Services span South Africa, EU, and global markets with varying compliance requirements
- **B2B and B2C Balance:** Security audits (B2B) and consumer apps (B2C) require different operational approaches

**Success Measurement - Stremiium KPIs:**

- Metric 1: **Council Coordination Effectiveness** - Inter-council collaboration rate >85%, conflict resolution time <24 hours
- Metric 2: **Regulatory Compliance Score** - Zero FSCA/FICA violations, CASP license maintained, CARF reporting accuracy 100%
- Metric 3: **Token Ecosystem Health** - $STM token utility across all 7 services, burn rate on target, staking participation >30%
- Metric 4: **Product Development Velocity** - Feature delivery rate, smart contract audit turnaround <14 days
- Metric 5: **Security Posture** - Zero critical vulnerabilities in production, penetration test findings resolved <48 hours
- Metric 6: **Cross-Vertical Integration** - User journey completion rate across multiple Stremiium services

**Key Constraints & Boundaries - Stremiium Specific:**

- **Regulatory Compliance:** All councils must operate within FSCA, FICA, POPIA, and (where applicable) National Gambling Act requirements
- **Token Interdependence:** Changes to any service must consider $STM token impact across the ecosystem
- **Data Sovereignty:** South African user data must remain within POPIA-compliant boundaries
- **CASP License Conditions:** Financial services councils must maintain "fit and proper" standards with regulatory examinations (RE5/RE1)

### Key Architectural Decisions (ADRs)

**ADR-001: Polygon as Primary Chain**

- **Decision:** Use Polygon PoS as primary blockchain
- **Rationale:** Low transaction costs, fast finality, Ethereum compatibility
- **Alternatives considered:** Ethereum mainnet (too expensive), Solana (different ecosystem)
- **Impact:** All smart contracts deployed to Polygon
- **Status:** Accepted

**ADR-002: Microservices Architecture**

- **Decision:** Use microservices over monolith
- **Rationale:** Independent scaling, team autonomy, technology diversity
- **Alternatives considered:** Monolith (simpler but less scalable)
- **Impact:** Each product is independent service
- **Status:** Accepted

**ADR-003: GraphQL for Primary API**

- **Decision:** Use GraphQL as primary API, REST for legacy
- **Rationale:** Flexible queries, strong typing, efficient data fetching
- **Alternatives considered:** REST only (simpler but less flexible)
- **Impact:** Client apps use GraphQL
- **Status:** Accepted

**ADR-004: Event-Driven Architecture**

- **Decision:** Use event-driven communication between services
- **Rationale:** Loose coupling, async processing, better scalability
- **Alternatives considered:** Synchronous REST calls (simpler but more coupled)
- **Impact:** Kafka/RabbitMQ for event streaming
- **Status:** Accepted

**Layer 3: Authentication & Authorization**
